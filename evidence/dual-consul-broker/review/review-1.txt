VERDICT: REWORK

All eight packet parts were read in full, including the truncated tail of part 04. I could not verify the manifest hashes or the reported test counts with Read alone, so every test claim below is taken from the packet, not measured.

**Summary.** The broker, store, gateway, client and grant loader are fail-closed on identity, authority, replay and fencing. Nothing in the increment runs by default, the installer defaults to a read-only check, and no scheduler or daemon is introduced. That makes the source acceptable to version as disabled, opt-in code. It is not yet acceptable as the privileged activation gate, because the installer can be made to install a setuid-root interpreter without changing the reviewed digest. The rest of the findings are liveness and contract gaps that should be fixed before the first canary.

**Findings**

1. **Installer preserves setuid/setgid bits that the reviewed digest does not cover (fix before any `--apply`).** In `scripts/provision_consul_broker.sh:104-111` root copies the caller-owned bundle with `ditto`, verifies content hashes, then runs `chown -R root:wheel` and `chmod -R go-w`. Neither `verify_tree` (lines 14-31, hashes and file types only) nor `infra/conductor/consul-broker/verify.py:81` (checks only uid 0 and `0o022`) rejects `0o6000` bits. `ditto` preserves modes, and a superuser `chown` on macOS does not clear setuid. Any process running as the ordinary caller UID can `chmod u+s` the bundled `python/bin/python3.11` after the digest is reviewed, and `--apply` then installs a world-executable setuid-root interpreter. Required fix: in the installer, after the copy, fail if `find "$RELEASE" \( -perm -4000 -o -perm -2000 \)` matches, or strip with `chmod -R u-s,g-s`, and normalise modes before the immutable check. In `verify.py`, extend the immutable check to `st_mode & 0o6022`. Both the apply and rollback paths run `verify.py --immutable`, so the second change also covers rollback.

2. **Lease window is shorter than the consumer's own worst-case bound, with no fenced renewal.** `consul_native_broker.py:335` binds with `lease_seconds=120`. The closed verb set in `scripts/conductor/protected_grants.py:138-143` has no renew or heartbeat verb. The consumer's stacked bounds exceed that: four helper exchanges at up to 20s each (`consul_broker_client.py:80`), the native turn at up to 60s (`codex_shadow.py:181`), plus thread start and two discovery RPCs at up to 10s each. If the lease lapses after `turn/start`, the guard refuses the `complete` check and the checkpoint, the consumer cancels, and a real spend ends as a cancelled run with a started attempt and no receipt. That is fail-closed but manufactures reconciliation cases. Required fix: derive the lease length from the consumer constants with margin (bounded by grant expiry), or make the `complete` check extend `lease_expires_at` under the same generation and row locks.

3. **Builder and reviewer identity check does not require the namespace prefix.** `consul_native_broker.py:205-208` derives `builder` and `reviewer` with `removeprefix` and only checks the residual set equals `{astra, fable}`. A producer named `astra` and a verifier named `fable` with no `com.balizero.consul.` prefix pass. The synthetic executor requires the exact prefixed name at `consul_executor.py:121` and `:155`. Required fix: require both names to start with the prefix before stripping it, and reject otherwise.

4. **Dead replay branch inside `checkpoint` reports the wrong status.** `consul_native_broker.py:528-532` returns `"recorded"` whenever a result already exists inside the guard, regardless of its terminal outcome. `_replay` at lines 647-654 correctly maps failed receipts to their native status and unknown receipts to `needs_reconcile`. The in-guard branch is only reachable in a race the guard itself refuses (parent no longer running), so it is dead today but wrong if the guard is ever relaxed. Required fix: factor the status derivation out of `_replay` and reuse it, or raise `needs_reconcile` in that branch.

5. **Counter contract: unknown native counters are dropped silently rather than made explicit.** `scripts/conductor/app_server_rpc.py:87-98` projects only the six known counter keys and discards the rest with no marker. `docs/architecture/dual-consul/common-contract.md:46` requires unknown fields to be explicit. Because the projection runs first, the broker's closed-field rejection at `consul_native_broker.py:695-712` is reachable only through test injection. Required fix: have the projection record the names of dropped counter keys (names only, no values) in a field that `_result` accepts, so a receipt shows when the native counter set diverged from the contract.

**Exact limitations on activation**

- Live activation is not justified. The `_nuz_consul` UID, the `nuzantara_consul` role, the mode-0600 config, migration 307 on the operational database, and any protected grant are all uninstalled. PostgreSQL proofs ran on the disposable cluster with a fake RPC, and no test exercised the real UID boundary or a real provider.
- Astra is absent from all three native catalogs. The default model `gpt-6-astra` fails closed at discovery and there is no fallback, so no Astra canary is possible until fresh catalog evidence exists.
- Finding 1 must be closed before the operator runs `--apply` or `--rollback`. Findings 2 and 3 should be closed before the first canary.
- The sudoers rule grants the control channel to the entire `nuzantara` UID, which is also the UID that hosts the native model process. The claim that a model receives no control channel rests on the Codex sandbox and disabled tool features, not on the kernel boundary.
- The production `admit` path never reaches the rebind branch of `consul_store.bind`. Generation fencing above one is proven only by tests that call `bind` directly. A revoked, expired or paused mission cannot be re-admitted under a new grant with the same mission id.
- `role.sql` references `research_os_objects_id_seq` and assumes `/usr/local/libexec` exists on Pro. Neither is verifiable from the packet and both need DBA or operator confirmation.
- Replay of a committed receipt is refused after the lease window, so a lost checkpoint acknowledgement outside that window is a reconciliation case, not a replay.
