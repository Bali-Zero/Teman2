## A — omit-when-empty

The claim survives attack because the defence is layered, not doubled, and each layer catches a different mutation:

- Mapper stops raising a flag → committed bytes disagree with regeneration → red in `walk-corpus-determinism.test.ts` **before** anything reaches this table.
- Total loss (generator emits the field nowhere) → `assert carrying` fires with the regeneration command in its message.
- **Partial** loss — the case the first two guards miss (regenerate *and* delete the matching table rows in one wave PR) → the hardcoded `{"ACTIVITY_BOUNDARY": 6, "NOT_CERTAIN": 2}` in `test_every_disclosure_flag_reports_the_walks_it_rewrites` goes red, at both family granularity and single-walk granularity (6→5).
- Stale pin → the `set(pins) - set(walks)` arm plus `carrying == set(EXPECTED_DISCLOSED_REVIEW_FLAGS)`.

The only way through all four is editing the pin in the same PR, which is the repo's normal reviewable-wave discipline. Claim holds.
