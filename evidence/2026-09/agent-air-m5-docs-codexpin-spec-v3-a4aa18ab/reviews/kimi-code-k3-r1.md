  1. **MAJOR — Task A: the "constants before the source" exclusion is unsafe for the two pin constants.** §5bis.3 excludes `CODEX_PIN_FILE` (wrapper l.63) and `PINNED_CODEX_ROOT` (l.64) — and equally `HOME_DIR`/`RUNTIME_DIR`/`VENV_PY`/`TAG`/`ORGAN_ID`/`SIDECAR_DIR` (ll.49–55) — with the rationale "deleting one either crashes under `set -u` … or matters only when launchd hands the process a hostile environment." A one-character edit to `PINNED_CODEX_ROOT` ships green through every contract-N/P test and through S3, and in production reads as "pin absent → legacy," i.e. silently re-opens F5's stale/wrong-DATA class. Fix: pin the constant lines with a content assertion (precedent exists: `test_wrapper_declares_pin_protocol_line`), or add them as anchor-only rows so any edit trips `STALE-ANCHOR`.

  2. **MAJOR — Task A: the 12-kind grammar does not capture negation prefixes or redirections, both of which are fail-open-capable deletions.** (a) `if ! _is_semver "$_wcbw_pin_ver"` (l.197): deleting just `!` applies every bad semver (`[bad_semver_planted]` resolves to the planted `9.9` tree) — a conjunct-level deletion that is no claimed site (G3 claims only `cond`) and produces no UNCLAIMED error. (b) `< "$CODEX_PIN_FILE"` on l.171: deleting it makes the NUL probe read stdin (empty/EOF under launchd and pytest), so a NUL-bearing pin passes the probe, is truncated by the l.178 loop to a valid line, and is applied — fail-open, again no site, no UNCLAIMED. Today both are backstopped only *indirectly*: the lines are anchors (so the edit trips `STALE-ANCHOR`) and the fixtures would turn the baseline red (`BASELINE-RED`). The spec should either add kinds (`negation`, `redir`) or state explicitly that these are anchor-protected non-sites whose only enforcement is the anchor plus the baseline contract.
