  **1. BLOCKER — `isClientModule` is defeated by this repo's own house style.**
  File: `apps/mouth/src/lib/client-roster-boundary.test.ts`
  > `return /^\s*(?:\/\*[\s\S]*?\*\/\s*)?["']use client["']/.test(source);`

  The regex tolerates one optional *block* comment before the directive, but not a *line* comment. Every new file in this very diff opens with a `//` header (`// apps/mouth/src/app/v2/_components/socialProofRoster.ts` — same for `book-team.ts` and `team-initials.ts`). A client component written in that house style — `// path comment\n"use client";\nimport { rosterBySlug } from "@/data/team-roster";` — is perfectly valid Next.js (comments before a directive are legal) yet `isClientModule` returns `false`, the offenders list stays empty, the guilt probes are unaffected, and both names ship in the chunk with every test green.
  Smallest fix: strip comments before the directive check, or extend the prefix group to `(?:(?:\/\*[\s\S]*?\*\/|\/\/[^\n]*)\s*)*`.

  **2. BLOCKER — `importsRoster` requires the literal word `from`.**
  File: `apps/mouth/src/lib/client-roster-boundary.test.ts`
  > `` new RegExp(`from\\s+["'][^"']*${hint.replace("@/", "")}["']`) ``

  Four import shapes carry the roster and match nothing: `import "@/data/team-roster";` (side-effect, no `from`), `await import("@/data/team-roster")`, `require("@/data/team-roster")`, and whitespace-free `import{x}from"@/data/team-roster"` (valid JS; `\s+` fails). Any of these in an existing client module — say `NavWhatsAppCTA.tsx`, which the walker does visit — leaks with the tripwire green. Note the asymmetry: the tripwire itself admits prose is a hazard (`stripComments` exists), yet this check runs on raw source, so it simultaneously misses real imports *and* can be false-tripped by a comment like `// never import { x } from "@/data/team-roster" here`.
  Smallest fix: run `importsRoster(stripComments(src))` and match `(?:from\s*|import\s*\(?\s*|require\s*\(\s*)["'][^"']*data/team-roster["']`.
