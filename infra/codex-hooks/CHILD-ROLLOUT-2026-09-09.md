| Continuation                | Children return to their parent; nested delegation denied; no child writes a parent jump                                                                                                     | Top-level Claude jump implementation remains the installed implementation                                                                                                                                                                                                                                         |

`MANDATE_BUDGET_OFF=1` disables the added reservation gate for operator recovery; it does not disable sandbox enforcement or the child depth rule. Existing Claude kill switches remain honored. Codex `needs_attention` never reopens normal tools after a context boundary.

## Installation boundary

Codex installs three source files per CODEX_HOME and eight trusted native hook definitions. Existing hooks and credentials stay in place. Each profile has an update backup and a source-hash manifest.

Claude installs `child_workflow.py`, `child_context.py` and the exact shared `mandate_budget.py` beside the current hooks. Only the existing PreToolUse context handler and SubagentStop handler are routed through this wrapper; SubagentStart adds the child contract. The wrapper invokes the exact installed context guard for the parent. The original context guard, stop guard and orchestrate gate remain byte-identical, verified before/after installation. Their existing per-host differences are not overwritten with this worktree's older repo copies. No SessionStart contract injection is added.

A profile with no previous context/stop hook receives these specific handlers pointing at the shared primary hook directory. Settings symlinks remain symlinks. The installer validates all target commands and source syntax before writes, then atomically replaces each adapter file with dependencies first. Rollback restores that profile's backed-up settings and adapter files without replacing any legacy guard. For the capacity-only update, restore the old child router; an unused `child_context.py` can remain without affecting the old router.

## Review and tests

The first Fable implementation review rejected installation and identified fail-open context recovery, session-lifetime budget coupling and false UNKNOWN stop blocks. These were corrected before the canary. Followup accounting, nested delegation, an owned-process EOF race, checkpoint initialization and resumed-child stop markers were also corrected. The final wrapper design avoids changing the legacy guard files.

Regression checks cover first native fork metadata, inherited-history exclusion, parent/child state isolation, repeated denials, bounded stop reminders, exact continuation acknowledgement, zero-tool readers, shell/MCP mutation classification, expired unstarted reservations, strict total budgets, same-child resume accounting, deadline/cancel/EOF cleanup and narrow settings routing. Native probes independently read the fixture after a real child returns. Secondary profiles require separate configuration/hash validation; a primary-profile model probe does not prove a secondary credential works.

Claude capacity follow-up adds `child_context.py` to the existing child adapter. It reads the latest native assistant request, including cache input and the current output allowance, without summing lifetime usage or duplicate streaming records. A successful owned CLI probe calibrates `result.modelUsage[exact_model].contextWindow`, bound to host, profile, exact transcript CLI version, routing settings and the actual hook environment fingerprint. Permissions-only changes do not invalidate it. Calibration expires after seven days; a model/version/routing change or missing data returns UNKNOWN. User settings or the parent's configured window are never treated as the child's capacity.

The tool boundary is 40% when capacity is native or calibrated; otherwise it is an absolute 64,000 measured-token budget, with no fabricated percentage. Every child also has a cumulative 60-tool-call and 900-active-second budget. Idle time after Stop is excluded; a follow-up retains prior active time and tool count. An exhausted child returns a checkpoint; resuming does not erase the exhaustion. These checks run before the next tool, not as a watchdog interrupting an in-flight request.

Calibration is local metadata only. Run `native_claude_child_probe.py` under the target CLAUDE_CONFIG_DIR to refresh it, then repeat the probe to observe the calibrated consumer. Models or profiles without a current calibration still have the fallback limits. No scheduler or daemon was added. Legacy parent guards remain the installed originals.
