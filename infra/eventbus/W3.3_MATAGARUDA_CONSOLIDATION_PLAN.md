## Migration path (when ready, separate PR)

### Phase 1: Event-driven instrumentation (additive, non-breaking)

Add `eventbus.publish()` calls to the 9 agents WITHOUT changing their logic. Each agent emits:

- `bridge.adaptive` → emits routing decisions as `intel.collected` events
- `kg-linker` → emits link extractions as `learning.updated` events
- `gap.consumer` → emits gap detections as `intel.collected` (gap = research request)
- `kita-feed` → emits feed publication as `publish.completed` (channel=web)
- `public-channel` → emits IG/Telegram publication as `publish.completed`
- `daily-briefing` → emits as `learning.updated`
- `invalidation-sweep` → emits cache invalidation as internal event (or skip)
- `nlm-feeder-stream` → emits per-NB push as `intel.deduped` (already deduped at source)
- `nlm-expander` → emits as `learning.updated`

This makes them OBSERVABLE in our trajectory observatory without touching their core logic.

### Phase 2: Subscriber refactor (collapsing logic)

Once all 9 emit events, build a single **MataGarudaController** subscriber that handles all events
matching `intel.*` + `learning.*` from mata-garuda emitters. Logic move from individual scripts to
controller. Original scripts become "publishers only" (thin wrappers around the data they collect).

### Phase 3: LaunchAgent retirement

Once Controller proves stable for 2 weeks: bootout 7-8 of the 9 LaunchAgents, keeping only the data
collectors (e.g., kita-feed, nlm-feeder-stream) as thin publishers. The rest of the logic lives in
Controller.
