# Intel Lake → NB-INTEL Pusher (Tier 1.5)

**Status**: ACTIVE on Pro since 2026-05-13 04:24 WITA.
**Purpose**: Push `intel_items.routing_status='nb-intel'` rows to their target
NB-INTEL notebooks via `nlm source add`. Closes the gap discovered after
A2 router shipped (PR #645): the router was classifying items but
nothing was reading the classification, so the routing was inert
telemetry.

This is **Tier 1.5** because it sits between the regex router (Tier 1,
PR #645) and a future LLM-based router (Tier 2). All it does is execute
the routing decision the regex already made.

## Pipeline

```
  intel_items (PG, Fly)
   routing_status='nb-intel'                              ──┐
   routing_targets={"nb_uuids":[<NB-INTEL UUID>,...]}     ──┤
                                                            │ every 15min
                                                            ▼
       ┌──────────────────────────────────────────────────────────┐
       │ Pro LaunchAgent                                          │
       │ com.balizero.intel-lake-nb-pusher.15min                  │
       │  → intel-lake-nb-pusher-cron.sh                          │
       │     - flock /tmp/intel-lake-nb-pusher.lock               │
       │     - nlm auth fail-fast                                 │
       │  → intel-lake-nb-pusher-standalone.py                    │
       │     - INSERT junction rows (item × nb_uuid) on conflict  │
       │     - SELECT pending FOR UPDATE SKIP LOCKED              │
       │     - URL push primary, text fallback                    │
       │     - per-class error retry policy                       │
       │     - UPDATE junction status + audit log                 │
       └────────────────────────────────┬─────────────────────────┘
                                        │
                                        ▼
           nlm source add <uuid> --url <canonical_url>
              ↓
           NB-INTEL-{Immigration|Tax|Regulation|AI|Press}
```

## Junction table (migration 171)

```sql
CREATE TABLE intel_item_nb_pushes (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    item_id UUID NOT NULL REFERENCES intel_items(id) ON DELETE CASCADE,
    nb_uuid UUID NOT NULL,
    content_hash TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending'
        CHECK (status IN ('pending','pushed','failed_transient','failed_permanent','quarantined')),
    attempts INT NOT NULL DEFAULT 0,
    pushed_at TIMESTAMPTZ,
    last_error TEXT,
    last_error_class TEXT,
    push_method TEXT,   -- 'url' | 'text'
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (item_id, nb_uuid, content_hash)
);
```

The composite UNIQUE constraint is the load-bearing piece — it lets the
pusher discover new (item, NB) pairs idempotently via `INSERT ... ON
CONFLICT DO NOTHING`, and it prevents the same content from being
pushed twice if the cron fires twice (or a future Fly-side pusher comes
online).

## Routing target data fix (collateral)

During smoke I discovered the 4 routed items had `routing_targets`
stored as **JSON-encoded strings** (jsonb scalar) instead of jsonb
objects — so `routing_targets ? 'nb_uuids'` returned false. Repaired
via `UPDATE ... SET routing_targets = (routing_targets#>>'{}')::jsonb
WHERE jsonb_typeof(routing_targets) = 'string'`. Source of damage
unknown (possibly a pre-A2 router run); the current A2 router cron
(PR #645) uses `json.dumps(dict)::jsonb` which round-trips correctly to
jsonb object — empirically verified after the fix.

## Operational notes

- **Schedule**: every 15 min (NLM rate limit comfortable margin: 10 items × ~7s = 70s wall, vs 900s interval)
- **Log**: `~/logs/intel-lake-nb-pusher.log`
- **Metrics**: `~/logs/intel-lake-nb-pusher.metrics.json` (last_run, pending_count, oldest_pending_age, per-class failures)
- **Lock**: `/tmp/intel-lake-nb-pusher.lock` (overlap prevention)
- **Auth**: NLM CLI `nlm login --check` at startup. Failure → Telegram + exit 2
- **Capacity**: 10 items/batch × 96 ticks/day = 960 items/day (Indonesia + Bali Zero scope sufficient)

## Retire path

This pusher is **permanent**, not transient. NLM CLI requires user OAuth
state in Pro keychain — there is no Fly-side equivalent. If a future Fly
EventBus listener re-enables and routes items in real-time, both can
coexist safely (UNIQUE constraint prevents double-push). But the actual
NB write will always be Pro-local because of OAuth.
