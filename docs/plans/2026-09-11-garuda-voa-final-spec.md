## 5. What was decided by measurement, not by opinion (so the windows do not re-litigate)

- `RESET ALL` preserves `current_user` after `SET ROLE`; `DISCARD ALL` does not (PG 17.10, measured). asyncpg ≥0.30 release query = `pg_advisory_unlock_all; CLOSE ALL; UNLISTEN *; RESET ALL`. The per-acquire `setup` hook in #6123 is therefore not load-bearing for RESET ALL but IS for an explicit `RESET ROLE` by a borrower; it stays, idempotent. The comment in `migration_base.py` that credits RESET ALL is wrong and W1R corrects it.
- A bare `SET ROLE backend_rag_v2` raises 42704 on CI (postgres:15 service, superuser `test`, role absent) and `apply-all` walks every file in `migrations_v2/` — so 304's closing bracket must be fail-safe (W1S). Migration 305 is a privilege-guard precedent, not a role-restore precedent.
- Astra's pack overstated the "two-line bracket": its PG17 proof always created the roles and never ran the CI role-absent shape. Its runner patch is pinned to the pre-council snapshot (`be45266252` working tree) and must be re-derived on `2a9941ab`.
- The single-DSN runner path is an unconditional no-op (no catalogue read), so production behaviour is unchanged until `MIGRATION_DATABASE_URL` exists.
