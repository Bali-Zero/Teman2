# What FASE 4 actually requires (synthesis)

To honor the brief's *intent* ("activate the HGT pathway end-to-end so
≥1 skill is exchanged within 24h"), the work is:

1. **Implement `CrmHGTPublisher` Sprint 4 wiring** (~30 LOC). Add a
   redis client param + actually call `xadd`. Add a runnable adapter
   that reads candidate patterns from CRM telemetry (where? — needs a
   product decision: Brevo template stats? WhatsApp delivery logs?).
   This is implementation, not activation.

2. **Wire `IntelScraperCellRunner` into `run_intel_pipeline.py`** (~50 LOC).
   The pattern-extraction surface (what counts as a "structural pattern"
   in scraper output) needs a product decision. Once decided, the
   runner already does the rest.

3. **Decide consumer daemon vs sentinel-cell rehab**. Either author a
   simple daemon (`scripts/run_hgt_consumer.py`) that loops `consume_once()`
   every 60s, OR rehabilitate `run_sentinel_py.py` to use the `_SentinelPulseLoop`
   with HGT integration. The latter risks coupling HGT to the sentinel
   cron schedule (daily). The former is cleaner.

4. **THEN** ship the 3 plists per brief.

Steps 1-3 are not "activate what's built" — they are "build what's
designed but not implemented." The brief should be reframed as FASE 4a
(implementation) → FASE 4b (activation), with 4a alone consuming a
multi-day work block.
