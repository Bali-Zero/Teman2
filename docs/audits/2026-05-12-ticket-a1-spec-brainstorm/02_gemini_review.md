# Architectural Review — TICKET A.1 Narrow Spec

**Verdict**: **BLOCK**

### Q1 Answers

- **Q1.1**: The `procedure` string formatting is **impoverished and functionally broken**. Because `HGTPublisher.publish()` strictly maps explicit fields for the Redis `xadd` payload and drops unrecognized fields like `_metadata`, the joined string is the _only_ data that survives. It is highly coupled to dictionary contents and lacks semantic richness. It must follow the `IntelScraperHGTBridge` pattern by requesting explicit, human-readable strings for `procedure`.
- **Q1.2**: The `success_criterion` hardcoded boilerplate is **too rigid**. Different CRM patterns (e.g., email bounce rate vs. WhatsApp response timing) require distinct validation horizons. This must be parameterized per `StructuralPattern` to align with the `IntelScraperHGTBridge` standard.
- **Q1.3**: The mock semantics in Test 7 are **flawed**. The `RuntimeError` generated by `mock_redis.xadd.side_effect` is caught and swallowed by `cell_core.hgt.publisher.HGTPublisher.publish()` which then returns `False`. The `except Exception as exc:` block within `CrmHGTBridge.publish()` is never reached. Consequently, the log capture targeting `"crm_cell.hgt_publisher"` will fail to find the exception warning because it is logged under `"cell_core.hgt.publisher"`.
