# Curator Agent — GARUDA Asset Indexer & Multi-Channel Publisher

**Status:** Design — Sprint 5 Mata Garuda
**Date:** 2026-04-14
**Author:** Zero + Claude Opus 4.6
**Context:** Mata Garuda Layer 4.5 (new)
**Cost target:** $0.00 operational (zero API paid, all local Ollama + CLI + OAuth)

---

## 1. PROBLEM

Bali Zero has accumulated significant creative-editorial material: 2831 MDX articles (already in Qdrant `balizero_news`), hundreds of AI-generated images, dozens of Flow/Veo video clips, ElevenLabs voiceover, NLM podcast, intelligence products, research dumps, carousel JSONs. This material lives scattered across:

- Local filesystem (`~/Downloads`, `/tmp/carousel_bali_sea`, War Room output)
- Tigris S3 bucket (`nuzantara-warroom-images`)
- Google Drive (unindexed archive)

Mata Garuda's current design is a **broadcaster**: produce once, fan-out to N channels. What is missing is a **curator / assignment desk**: an agent that queries a pool of assets, selects the best for a specific channel and timing, composes the final product, and publishes.

**Constraint:** CRM, PERATURAN, CLIENTI, CONTRATTI folders on Drive are out of scope — they contain sensitive/operational data and are already organized elsewhere (Qdrant `peraturan`, PostgreSQL CRM tables).

---

## 2. SOLUTION OVERVIEW

A dedicated Google Drive folder `GARUDA/` as the single source of truth for all creative-editorial assets. A daily indexer agent crawls new/modified files incrementally (50 files/night), extracts metadata + embeddings via local Ollama, stores in a dedicated Qdrant collection. Channel-specific sub-curators query this pool, compose products, and publish.

## 3. COMPONENTS

### 3.1 `garuda_indexer` — Daily incremental indexer

**Location:** `apps/zantara-media/indexer/` (new app in monorepo)
**Runtime:** Python 3.11 + Ollama local + Whisper + Tesseract
**Scheduling:** OpenClaw cron, 03:00 WITA daily
**Throughput:** 50 files/night (tunable)

**Flow:**

```python
# Pseudocode
for file in gdrive.list_modified(
    folder_id=GARUDA_ROOT,
    since=last_scan_at,
    limit=50,
    recursive=True,
):
    if file.mime in TEXT_TYPES:         # PDF, Doc, txt, md
        text = extract_text(file)        # pypdf / Google Docs API / Tesseract
    elif file.mime in IMAGE_TYPES:       # jpg, png, heic
        description = qwen25vl_describe(file)
        text = description
    elif file.mime in VIDEO_TYPES:       # mp4, mov
        frames = ffmpeg_extract_frames(file, at=[0, 0.5, 1.0])
        text = qwen25vl_describe_multi(frames)
    elif file.mime in AUDIO_TYPES:       # mp3, m4a, wav
        text = whisper_transcribe(file, model="medium")

    embedding = ollama_embed(text, model="bge-m3")  # 1024 dims

    postgres.upsert("garuda_index", {
        "file_id": file.id,
        "path": file.path,
        "name": file.name,
        "mime_type": file.mime,
        "size_bytes": file.size,
        "modified_at": file.modified_time,
        "parent_folder": file.parent_id,
        "extracted_text": text[:5000],
        "indexed_at": now(),
    })

    qdrant.upsert("garuda_assets", {
        "id": file.id,
        "vector": embedding,
        "payload": {
            "file_id": file.id,
            "category": guess_category(file.parent_id),
            "mime": file.mime,
            "name": file.name,
            "path": file.path,
            "description": text[:500],
            "tags": auto_tag(text),
            "modified_at": file.modified_time,
        }
    })

    save_state(last_scan_at=file.modified_time)
```

**Skip rules:**

- Files already indexed with same `modified_time` → skip
- Files > 500MB → skip (log for manual handling)
- Files with `content_hash` collision → update only if timestamp newer
- Files in `published/` older than 180 days → move to cold storage (mark `archived=true`)

**Catch-up mode (B2 first weekend):**
On first run, if `garuda_index` is empty, switch to `CATCH_UP` mode: 500 files/hour instead of 50/night. Run overnight Friday+Saturday until pool < 50 unindexed. Then revert to daily incremental.

### 3.2 PostgreSQL schema

Three new tables in `nuzantara-postgres` Fly.io. New Alembic migration `migration_108_garuda_curator.py`.

```sql
-- Master index of all GARUDA files
CREATE TABLE garuda_index (
    file_id VARCHAR(128) PRIMARY KEY,           -- Google Drive file ID
    name VARCHAR(512) NOT NULL,
    path TEXT NOT NULL,                         -- breadcrumb from GARUDA root
    parent_folder VARCHAR(128) NOT NULL,        -- e.g. '1c9QnRb22Xdcr...' for photos
    category VARCHAR(32) NOT NULL,              -- photos|videos|audio|intelligence|drafts|research|published
    mime_type VARCHAR(128) NOT NULL,
    size_bytes BIGINT NOT NULL,
    modified_at TIMESTAMPTZ NOT NULL,
    indexed_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    extracted_text TEXT,                        -- first 5000 chars
    description TEXT,                           -- short LLM-generated description
    tags JSONB DEFAULT '[]',                    -- auto-tags from content
    content_hash VARCHAR(64),                   -- SHA-256 for dedup
    archived BOOLEAN DEFAULT FALSE,
    metadata JSONB DEFAULT '{}'                 -- type-specific metadata
);
CREATE INDEX idx_garuda_index_category ON garuda_index(category);
CREATE INDEX idx_garuda_index_modified ON garuda_index(modified_at DESC);
CREATE INDEX idx_garuda_index_archived ON garuda_index(archived) WHERE archived = FALSE;

-- Publication history across all channels
CREATE TABLE publication_history (
    publication_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    channel VARCHAR(32) NOT NULL,               -- ig_carousel|ig_video|tg_channel|newsletter|blog|x_thread|linkedin
    topic VARCHAR(512) NOT NULL,
    title TEXT,
    published_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    asset_ids JSONB DEFAULT '[]',               -- array of garuda_index.file_id used
    external_id VARCHAR(256),                   -- e.g. Instagram post ID, TG message ID
    external_url TEXT,
    language VARCHAR(8) DEFAULT 'en',
    engagement_metrics JSONB DEFAULT '{}',      -- filled by feedback loop later
    curator_agent VARCHAR(64) NOT NULL,         -- e.g. curator_ig_carousel
    autonomy_level VARCHAR(4) NOT NULL,         -- L1|L2|L3
    approved_by VARCHAR(64)                     -- telegram user if L2/L3
);
CREATE INDEX idx_pubhist_channel_time ON publication_history(channel, published_at DESC);
CREATE INDEX idx_pubhist_topic ON publication_history(topic);

-- Indexer state (resume / watchdog)
CREATE TABLE garuda_indexer_state (
    id SERIAL PRIMARY KEY,
    last_scan_at TIMESTAMPTZ NOT NULL,
    files_indexed_total BIGINT DEFAULT 0,
    files_indexed_last_run INT DEFAULT 0,
    errors_last_run JSONB DEFAULT '[]',
    next_scheduled_at TIMESTAMPTZ,
    mode VARCHAR(16) DEFAULT 'daily'            -- daily|catch_up
);
```

### 3.4 Asset pool builder

Runs every morning 08:00. Queries the freshest/most relevant pool for the day.

```python
def build_daily_pool(target_date: date) -> dict:
    """
    Query garuda_index + balizero_news + redis streams.
    Build a 'ready-to-curate' JSON.
    """
    return {
        "date": target_date.isoformat(),
        "fresh_assets": qdrant.scroll(
            collection="garuda_assets",
            filter={"modified_at": {">=": target_date - timedelta(days=7)}},
            limit=200,
        ),
        "trending_articles": qdrant.search(
            collection="balizero_news",
            query_vector=daily_briefing_embedding(),
            limit=50,
        ),
        "intelligence_products": redis.xrange(
            "garuda:digest",
            min=to_ts(target_date),
        ),
        "recent_publications": postgres.query("""
            SELECT channel, topic, published_at, asset_ids
            FROM publication_history
            WHERE published_at > NOW() - INTERVAL '14 days'
            ORDER BY published_at DESC
        """),
    }
```

### 3.7 Scoring / selection logic

Every asset gets multi-dimensional scores. The LLM (Claude CLI via Max sub, or Ollama for autonomy) picks the top N per channel.

```python
def score_asset(asset, channel, topic) -> float:
    quality     = asset.quality_score                          # 0-1, from quality_gate.yaml
    freshness   = exp(-age_hours(asset) / channel.tau)         # tau varies per channel
    relevance   = cosine(asset.embedding, topic_embedding)     # 0-1
    diversity   = 1 - similarity_to_recent_publications(asset) # avoid repeat
    engagement  = asset.engagement_score or 0.5                # from history if used
    audience_fit = audience_match(asset, channel.audience)     # 0-1

    return (
        0.25 * quality +
        0.20 * freshness +
        0.20 * relevance +
        0.15 * diversity +
        0.10 * engagement +
        0.10 * audience_fit
    )
```

Per-channel `tau` (freshness decay half-life):

- X: 6 hours
- TG Channel: 24 hours
- IG carousel: 72 hours
- Newsletter: 168 hours (1 week)
- Blog: 336 hours (2 weeks)
- LinkedIn: 336 hours

## 6. RISKS & UNKNOWNS

| Risk                                              | Impact     | Mitigation                                                                                 |
| ------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------ |
| Ollama qwen2.5vl description quality inconsistent | Medium     | Fallback to Claude CLI for critical assets (first 100 uploads)                             |
| Google Drive OAuth token expires (90 days)        | Medium     | Reuse existing watchdog (CLAUDE.md §14)                                                    |
| Pro M4 CPU saturation during batch                | Low        | Run 03:00 when Core Guardian is idle; cap at 50 files                                      |
| bge-m3 semantic quality vs text-embedding-3-small | Low-Medium | Quality 85-94% on benchmarks; acceptable for curator pool                                  |
| Duplicate detection misses near-duplicates        | Low        | SHA-256 exact + vector cosine > 0.95 near-dup check                                        |
| Catch-up mode overnight fills disk                | Low        | Monitor Qdrant disk usage, auto-prune archived files                                       |
| Large video files (>500MB) timeout                | Low        | Skip + alert, manual handling                                                              |
| Sensitive content accidentally placed in GARUDA/  | High       | Pre-upload lint check: path must not contain "client_name", "invoice", "contract" keywords |
| Curator picks same asset repeatedly               | Medium     | Diversity score + max-reuse cap (3 times/6 months)                                         |
| LLM picks irrelevant assets for topic             | Medium     | Relevance threshold 0.65 minimum; L2 human review                                          |

## 10. OPEN QUESTIONS

1. Should `garuda_assets` live on local Qdrant or Fly.io Qdrant? Local = faster, cheaper; Fly.io = shared with other services. **Default: Fly.io for consistency**, switch to local if latency issues.

3. Should curators be implemented as separate OpenClaw jobs or as a single long-running daemon? **Default: separate OpenClaw jobs** for isolation + restart recovery.
4. Multi-lingua IT/ID expansion: Phase 3 or during Phase 2? **Default: Phase 3** to avoid scope creep.
