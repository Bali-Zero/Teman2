# Partners v1.1 backlog

**Source:** Multi-LLM council review 2026-04-21 — `99-synthesis.md` §Important.
**Status:** All 12 Catastrophic + Critical items landed in PR #141. These 11 Important items are v1.1 scope.

Items grouped by theme. Each lists the council reviewer who flagged it, rough effort, and the risk if not done.

## Security / data integrity (highest priority)

### IMP-6 — Email TOCTOU + case-sensitivity guards (2-3h)
**Flagged:** Codex, Gemini, DeepSeek.
**File:** `services/crm/partners/repository.py::_assert_email_is_not_internal`.
**Issue:** SELECT-then-INSERT race between partner creation and internal user creation. Also: check is case-sensitive; `Admin@balizero.com` and `admin@balizero.com` treated as different.
**Fix:** Wrap create_partner in `BEGIN ISOLATION LEVEL SERIALIZABLE; ... COMMIT;`. Also add `LOWER()` on both sides of the comparison; normalize email to lowercase on insert.
**Risk if ignored:** Narrow window where a partner can be created with an email matching an admin/team user. Impact: authentication confusion, potentially role escalation depending on token-lookup behavior.

### IMP-4 — Audit log partner self-access (1h)
**Flagged:** Codex.
**File:** `app/routers/partners.py::list_partner_audit_log`.
**Issue:** The audit endpoint uses `verify_partner_access_with_role` which allows partner role. Partners can therefore see their own audit log rows including `actor_user_id`, reason text for reassignments, and full before/after JSON snapshots (may contain fields partners should not see, e.g., other team member's email in reassignment reasons).
**Fix:** Gate with `_require_team_or_admin` — partners should not read their own audit log in v1. v1.1 can add a sterilized partner-facing audit view later if needed.
**Risk if ignored:** Minor PII/internal-ops leakage to partners via their own audit tab.

### IMP-5 — `update_partner` audit failure mode (30m)
**Flagged:** Codex.
**File:** `services/crm/partners/service.py::update_partner`.
**Issue:** Partner row updates first, then `json.dumps(before, after)` serializes audit payload. If `before`/`after` contains Decimal or datetime, json.dumps raises ValueError → audit entry not written → 500 returned to user, but the UPDATE already committed.
**Fix:** Use a defensive JSON encoder (`default=str` fallback). Alternatively, serialize before writing the partner row — if json.dumps fails, abort the whole transaction.
**Risk if ignored:** Audit trail silently gets gaps; compliance/forensic investigations harder.

## Workflow correctness

### IMP-1 — Inactive partners can still receive referrals and accrue (45m)
**Flagged:** Codex.
**File:** `services/crm/partners/repository.py::insert_referral`, `commission_engine.py::accrue_from_practice`.
**Issue:** Neither checks `partner.onboarding_status == 'active'`. UI filters but API is the enforcement boundary.
**Fix:** Reject referrals where partner is not `active`. Reject accrual (log warning, no-op) where partner is `inactive`/`pending_approval`.
**Risk if ignored:** A team member can attach a pending-approval partner to a practice. The partner would accrue silently, and if admin later activates the partner, the commission appears in their portal with no record of the timing.

### IMP-2 — Bulk reassignment is not atomic (30m)
**Flagged:** Codex.
**File:** `app/routers/partners.py::bulk_reassign`.
**Issue:** Router loops through `partner_ids` calling `svc.reassign_partner` one at a time. If the 3rd fails, the first 2 are reassigned but the 4th+ are not, and the admin sees a 500.
**Fix:** Wrap the whole loop in `async with conn.transaction():`. If any partner fails, roll back all.
**Risk if ignored:** Partial reassignments leave the admin doing manual cleanup.

### IMP-11 — Process creation silently logs referral failure (15m)
**Flagged:** Codex.
**File:** `apps/mouth/src/app/(workspace)/process/new/page.tsx`.
**Issue:** After `createPractice` succeeds, `createReferral` is called in a try/catch that only `console.warn`s on failure. User thinks referrer is saved.
**Fix:** Show a toast warning: "Practice saved but referral link failed — please add referrer manually from the practice detail page." Or: block the save until both succeed.
**Risk if ignored:** Referrals silently dropped on transient network errors. Commissions never accrue for that practice.

### IMP-3 — Partner commission notifications not EventBus-backed (1h)
**Flagged:** Codex.
**File:** `services/crm/partners/events.py`, router `mark_paid_commission`.
**Issue:** `partner.commission_changed` channel is only published on accrual. approve/pay/clawback don't publish. The "email on mark-paid" is direct router side-effect code, not a subscriber.
**Fix:** Publish `partner.commission_changed` with `type='approved'` / `type='paid'` / `type='clawback'` from the engine. Let downstream subscribers (email, analytics, future webhooks) react uniformly.
**Risk if ignored:** Adding a new downstream consumer (e.g., Slack notification on paid) requires editing router code. Not a correctness bug, just design debt.

## Production hardening

### IMP-10 — Brevo circuit breaker + retry budget (3h)
**Flagged:** DeepSeek.
**File:** `services/crm/partners/emails.py`.
**Issue:** Current outbox (v1) retries with backoff 1m/5m/30m/2h/8h. If Brevo is down for 8 hours, the outbox drains slowly and new emails queue behind it. No circuit breaker skips retries during a confirmed outage.
**Fix:** Add a simple circuit breaker: if 5 consecutive attempts across different outbox rows all fail with 5xx, open circuit for 15 minutes. Test flush-endpoint behavior under breaker-open.
**Risk if ignored:** A 2-hour Brevo outage produces a 6-hour email backlog.

### IMP-8 — NB-2 recommends hard-block on sponsor/garante/penjamin work_role (15m)
**Flagged:** NB-2.
**File:** `services/crm/partners/service.py::activate_partner`.
**Issue:** Current UI shows soft warning on `work_role` regex match. Service layer does not enforce. Activation proceeds regardless.
**Fix:** Block activation at service layer if `work_role` matches `/sponsor|garante|penjamin/i` unless admin passes an `override_reason` kwarg. Save the override reason in the audit log.
**Risk if ignored:** A typo/mislabel leads to SIMKIM data mismatch per NB-2's One Sponsor Policy concern.

### IMP-9 — Finance CSV no date-range cap (15m)
**Flagged:** DeepSeek, Codex.
**File:** `app/routers/partners.py::finance_export`.
**Issue:** User can `?from=2000-01-01&to=2099-01-01` → export everything.
**Fix:** Cap max range at 366 days. Also add audit log entry for each CSV export (who, when, range).
**Risk if ignored:** Mass PII export vector if an admin account is compromised.
