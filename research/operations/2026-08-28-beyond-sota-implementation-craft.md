# 4/13 — Implementation craft (BUILD): how code actually gets written in this organism

## 0. TL;DR

**Position**: ahead of every surveyed system on *tree* isolation (a broker with TTL, RAM admission, 2-AND reap, fleet placement — nothing surveyed matches it) and on routing breadth (7 builder families on flat subscriptions); behind SOTA on *environment* hermeticity, on the stop boundary, and on making its own contracts show up in its own meters.
**Biggest gap**: the organism believes isolating the git tree isolates the work. Everything the tree does not contain is shared and undeclared — venv/node_modules/DB (60 tests red in a worktree, green in CI, same commit), the machine (13 of 14 spawns died ENXIO; the suite lock left 30 % of pushes verdict-less and forced the local gate DEFAULT-OFF), the stop boundary (headless lanes exited 0 with work undone), the quota pool, and the default model (85.8 % Sonnet dispatches against a workhorse-first ruling; fix-share of main commits 30.6 %).
**Top-3 moves**:
1. **Check-gated stop** — a `.lane-check.json` Definition-of-Done per worktree, consumed by all four termination surfaces (interactive stop, subagent stop, headless report detector, PENDING-ARMS auto-row).
2. **Per-lane outcome telemetry** — correction-chain rate, time-to-green, builder attribution from the branch namespace: the internal METR that every other move's metric depends on.
3. **Hermetic lane tier** — per-worktree env + per-lane Postgres in the broker; earns local verification back (pre-push DEFAULT-ON) and retires the machine-wide suite lock.

### The five that matter most

**S4 + S3 (Anthropic) — the check gates the stop.** The documented state of the art is now explicit: a check the agent can run, escalated from prompt → `/goal` → **Stop hook that refuses to end the turn until the check passes** → fresh-context refuter. The organism has every ingredient (spec on disk from DESIGN, `stop_verify.py`, `subagent_stop_verify.py`, report-file contract for `-p`) but wires the Stop gate to *git cleanliness*, not to *the lane's check*. That is why "exit 0 with the work undone" (two headless runs) and "silent-idle before the last mile" (5+ lanes) exist: nothing at the stop boundary asks whether the acceptance criterion passed.

**S5 (Cognition) + the 9-lane/14-spawn incidents — parallelism is only safe over disjoint scope.** Cognition's argument is not "never parallelize"; it is that parallel actors make *unstated* decisions. `fleet_dispatch.py` already makes scope *stated* (`--files`, `.scope`). The failures came from parallel lanes sharing what scope files cannot express: one Postgres, one venv, one machine's RAM (13 `fork failed`), one pre-push lock. Scope must extend from *files* to *environment and capacity*.

**S8 + S9 — hermetic per-task environments are the SOTA primitive; the worktree is not one.** Every leaderboard agent runs in a container that owns its interpreter, dependencies and database. Here the broker symlinks `.venv`, `.env`, `node_modules` to the main checkout by design (runbook §"Effetti"), and the venv is live infrastructure for 7 daemons. The measured consequence: 60 tests red in a worktree and green in CI on the same commit; pre-push local suite forced DEFAULT-OFF because the *shared* lock made 30 % of pushes verdict-less. Hermeticity is the one move that unlocks local verification again.

**S1 + S2 — size is enforced by structure, not by prose.** Google and Meta both make smallness *cheap* (stacks, absorb, split recipes, typed exceptions) rather than merely *required*. The organism has the rule, the merge queue and the measurement, but no split recipe and no exception taxonomy — so a quarter of merges exceed the contract and nobody can say which were legitimate.

**S6 + S7 — measure delivered outcome, not activity.** METR's 19 % and DORA's throughput-up/stability-down are the same warning: without an outcome metric per lane (time-to-green, fix-follow-up within 7 days, reverts), a fleet can be busier and slower. SEAT-MIX meters seats; nothing meters *whether a lane's PR needed a correcting commit*.

## 5. Beyond-SOTA recommendations

Ranked by (impact × confidence) / cost. All costs are flat-subscription tokens + session hours (no paid API anywhere). "Scar risk" names the superscar family the move could itself trigger.

**R1 — The lane check gates the stop: a machine-readable Definition-of-Done per worktree.**
*What*: DESIGN emits a `.lane-check.json` into the worktree (command, expected exit, timeout, scope globs); the stop boundary consumes it on **all four termination surfaces**: interactive Stop hook, `subagent_stop_verify.py`, the headless report-file detector, and the PENDING-ARMS entry (a lane that stops with the check red auto-writes its own ledger row). *Why beyond SOTA*: S4 documents a check-gated Stop hook for one surface; no surveyed system unifies interactive/subagent/headless/cron termination on one on-disk contract — and this organism is the only one whose delivery failures are *measured* at that boundary (2 headless exit-0-undone, 5+ silent-idle lanes, AMENDMENTS 2026-07-14/16). Exploits: hooks-as-backstop + spec-on-disk from modus DESIGN + the ledger. Deliberately BUILD-side: this is the builder's self-check, not lane 5's adversarial gate — generator≠grader still applies after it. *Cost*: ~2 sessions, ≤600 lines total. *Gear*: 2. *Scar risk*: #3 (the check matcher itself over/under-matches — it goes through `infra/guard-conformance/` with guilt+innocence tests) and #2 (a tautological check = theater; the anti-reward-hacking linter must cover `.lane-check.json` commands). *Metric*: silent-idle/exit-0-undone occurrences per 30 days (baseline ≥7 across AMENDMENTS + the headless lesson) → 0; measured by grepping AMENDMENTS + task reports. *Kill criterion*: >20 % false blocks (check red but work genuinely done) in 14 days → revert to git-dirty gating. *First PR*: below (PR-1).

**R2 — Per-lane outcome telemetry: the internal METR.**
*What*: a read-only script that, for every merged PR, computes (a) **correction-chain rate** — did a `fix`-prefixed commit/PR touch the same files within 7 days (the "27 of 200" number, automated); (b) time-to-green; (c) builder attribution from the `agent/<host>/<lane>/` namespace + claim commit; published as a daily SEAT-MIX section. *Why beyond SOTA*: DORA measures stability at survey scale, METR at RCT scale; nobody instruments per-seat correction-rate on a live multi-family fleet — the branch namespace and claim-commit convention make attribution free here, an asymmetry no surveyed shop has. It also converts the 30.6 % fix-share from an anecdote into a steering signal for R4/R5. *Cost*: 1 session, ~250 lines. *Gear*: 2. *Scar risk*: #2 (a metric nobody reads is theater — it lands in the digest, not a file); Goodhart (builders gaming "no fix commits" by mislabeling — mitigated by file-overlap detection, not prefix alone). *Metric*: the metric IS the deliverable; acceptance = it reproduces the hand-measured 27/200 window within ±3. *Kill criterion*: attribution coverage <60 % of merged PRs → the namespace convention is the real gap, fix that first. *First PR*: PR-2.

**R3 — Hermetic lane tier: extend the broker's invariant from tree to environment.**
*What*: an opt-in `--hermetic` tier in `agent_start.py`: per-worktree Python env built from the lockfile (uv-style frozen sync into the worktree, shared download cache; the live `.venv` that feeds 7 LaunchAgents is never touched), per-worktree node install from the repo's package manager with a shared content-addressed store (assumption stated: store support exists; else plain per-worktree install), and per-lane Postgres (template-DB clone or per-lane schema, dedicated port). Hermetic lanes then get: local pre-push suite **DEFAULT-ON** again, and exemption from the machine-wide single-flight suite lock — the lock exists *because* the DB is shared. *Why beyond SOTA*: container-per-task is the S8 baseline, but no surveyed system composes hermetic envs with a broker that does TTL, RAM/swap admission, 2-AND reap and fleet-wide placement on always-on local hardware — and none earns the *removal of a serialization lock* as the dividend. *Cost*: ~4 sessions across 3 PRs; disk (bounded by shared caches — see needs-ruling on Pro headroom). *Gear*: 3 (architectural; CI-recomputed floor will agree). *Scar risk*: #1 (a per-lane env is a new copy that can drift — antidote: built from the lockfile every time, never patched in place), #5 (port/DB-name collisions — broker allocates from its registry). *Metric*: (a) worktree↔CI divergence: 60/4,414 red-local-green-CI → 0 on an A/B at constant commit; (b) pushes with a local verdict: ~0 % (DEFAULT-OFF) → >70 % on hermetic lanes; (c) 9-lane shared-DB collision class: impossible by construction. *Kill criterion*: hermetic setup p50 >120 s or >25 GB steady-state disk → tier stays opt-in for DB-touching lanes only. *First PR*: PR-4 (wave 2).

**R4 — Make the 400-line contract structural: typed exceptions + split recipes.**
*What*: adopt Google's two missing pieces, machine-checked because there is no human reviewer to apply judgment: an exception taxonomy by path-class and provenance (docs/design reports, codemod output with the tool named in the PR body, lockfiles, generated fixtures) and split recipes in the contract (by-files, horizontal, vertical, stacked child-PR as the arm-freeze-compatible follow-up). ## 8. §Meta-pattern

The single defective belief that generates the findings of this lane: **"isolating the git tree isolates the work."** The broker made working_tree(w₁)∩working_tree(w₂)=∅ true and battle-hardened (superscar #5's antidote, genuinely ahead of SOTA), and the organism inferred lane independence from it. But the unit of work is larger than the tree, and every leak in §2/§4 is a shared, undeclared resource acting as an interference channel: the **environment** (symlinked venv/node_modules, one Postgres → 60 red-local-green-CI tests, the 9-lane DB pileup, W96 writing production state), the **machine** (RAM/fork → 13 ENXIO of 14 spawns; the single-flight suite lock → 30 % of pushes verdict-less, local suite DEFAULT-OFF), the **stop boundary** (exit-0-with-work-undone, silent-idle — the turn is shared between "done" and "stopped" with nothing arbitrating), the **quota pool** (14 % of Kimi's month in one day), and the **default model** (85.8 % Sonnet against a workhorse-first ruling). The corollary that kept it invisible: *"a written contract is a practiced contract"* — family #2 applied to craft doctrine (400-line rule vs p90 = 1,292; routing ruling vs the meter; TDD "where testable" unmeasured). The unifying cure, of which R1/R2/R3/R5 are instances: extend the broker's invariant from trees to **"resources(w₁)∩resources(w₂) is declared and brokered"** — env, DB, locks, RAM, quota, stop-check — and give every craft contract its meter at birth, because here a contract without a meter is not conservatively ignored, it is silently violated at p90.
