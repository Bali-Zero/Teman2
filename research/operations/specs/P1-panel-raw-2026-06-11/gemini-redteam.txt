1. **SEVERITY: BLOCKER** | **Section Ref: §1.4 & §4 R4**
   **Defect**: The stage workers (e.g., `wr2_html_render_apply.py` and `wr2_draft_generator.py`) enforce a strict batch limit per execution (`MAX_DRAFTS_PER_RUN = 1` or `2`). The supervisor uses `launchctl kickstart` to trigger these transient agents upon receiving a PostgreSQL `wr2_status_change` notification. If a new draft transitions status while its corresponding agent is already running, the supervisor's `kickstart` call returns `rc=113` ("service is busy") because launchd refuses to spawn concurrent instances of the same LaunchAgent label. The running agent then exits after processing its current single draft without checking the database again.
   **Why it breaks**: The new draft is left stuck in its transition status (e.g., `drafts_imaged_checked` or `briefed`) and will not progress automatically. It remains stuck until the supervisor's periodic reconciliation loop runs (every 5 minutes) AND the draft's staleness exceeds `RECONCILE_STALE_MIN` (30 minutes). This introduces a severe throughput bottleneck where concurrent draft batches stall for hours.

2. **SEVERITY: HIGH** | **Section Ref: §2 S10 & §5 M9**
   **Defect**: The watchdog script `wr2_supervisor_watchdog.py` monitors the pipeline success rate by reading from `TELEMETRY_PATH = Path.home() / "logs" / "wr2_canva_apply_telemetry.jsonl"`. The consolidation spec updates the watchdog to gate checks on the `wr2_html_renderer_enabled` kill-switch instead of Canva. However, the HTML renderer script `wr2_html_render_apply.py` does not output any telemetry files, nor does it write to the Canva telemetry log.
   **Why it breaks**: Since no new telemetry entries are appended by the HTML lane, the attempts in the 7-day rolling window will drop to 0 after 7 days of Canva retirement. The watchdog function `_probe_success_rate_telemetry()` returns a default 100% success rate when attempts are 0. As a result, the watchdog will become completely blind to HTML rendering failures, failing to alert even if the HTML renderer experiences a 100% crash rate.

3. **SEVERITY: HIGH** | **Section Ref: §2 S1 & §3 Property 3**
   **Defect**: The spec proposes moving the `topic_type_log` insert (S1) directly into the database transaction of `_pg.persist_html_result_and_enqueue_notifications`, which resides in the backend application code (`apps/backend-rag/backend/services/canva_renderer_v2/_pg.py`).    **Why it breaks**: The root-level `scripts/` directory is outside the package boundaries of `apps/backend-rag/backend/` and is not included in the Python path of the FastAPI backend application in production or during unit tests. 4. **SEVERITY: MEDIUM** | **Section Ref: §1.4 & §3 Property 3**
   **Defect**: The PostgreSQL trigger `wr2_status_change_trg` inserts durable rows into `events_outbox` for each status change. However, the supervisor's live event listener pathway (`_on_notification` -> `_handle_payload`) never executes an UPDATE on `events_outbox`.
