# T1.5 — `alzheimer-diagnose.sh` Telegram alert

## Problem

Piano 2026-05-19 Item 7 (P0) richiedeva: emit Telegram alert quando MEMORY.md > 25KB. Empirical TODAY:

- `~/.claude/scripts/alzheimer-hook.sh` esiste con Telegram code + state file
- Last alert verified fired 2026-05-19
- MA piano nomina `alzheimer-diagnose.sh` (separato) — questo NON esiste
- Side-effect: 22+ orphan file (T0.1) detection già emessa ma alert non visibile a Antonello (forse silenziati 8gg)

Decisione: consolidare in `alzheimer-diagnose.sh` (script con threshold + alert + report)? OPPURE confermare che `alzheimer-hook.sh` esistente già fa quel lavoro e basta verifica empirica?

## Context

Empirical state (regression-fix-19 digest):

- File: `~/.claude/scripts/alzheimer-hook.sh` (existente)

- Telegram bot: `TELEGRAM_BOT_TOKEN` + `TELEGRAM_OWNER_CHAT_ID=1125336968` (Zero's chat)

Risk: Antonello chiede esplicitamente "alzheimer-diagnose.sh" — naming mismatch può creare confusione futura.

## Design

2 opzioni:

**Opt A (no-rename, verify-and-enhance)**: leave `alzheimer-hook.sh`, verifica che alert > 25KB attivo, fix se rotto. Documenta che `alzheimer-diagnose.sh` = `alzheimer-hook.sh` alias.

**Opt B (rename + enhance)**: rename `alzheimer-hook.sh` → `alzheimer-diagnose.sh`, aggiorna LaunchAgent + cron, refactor.

Recommend **Opt A** — meno rischio, no LaunchAgent breakage. Riportare allineamento naming convention in lesson capture.
