# T2.3 — Install GitHub MCP

## Problem

Nuzantara è Autonomous Ops L2: `git push`, PR create, auto-merge se CI green, deploy via `fly-deploy.yml`. Oggi opero via `gh` CLI (Bash). Funziona, ma:

- Ogni `gh pr view 123` = full file read, no caching
- `gh pr checks 123 --json ...` = jq parsing manuale
- Issue search = full text dump

GitHub MCP fornisce:

- `gh_pr_get(pr_number)` strutturato + cache
- `gh_pr_checks(pr_number)` con bucket auto-filtered
- `gh_issue_search(query)` semantic search
- `gh_workflow_runs(workflow_id)` con status enum

ROI: ~30% riduzione token per workflow PR-heavy.

Source: GitHub MCP server `ghcr.io/github/github-mcp-server` (Codex Part 2 #4, Nimbalyz #1, Anthropic best-practices doc).

## Context

PAT scope necessario: `repo`, `read:org`, `workflow` (least scope sufficient). Verifica esistente PAT su keychain.

## Acceptance criteria

- [ ] `github` MCP server in `.mcp.json` or `~/.claude.json`

## Implementation steps

### Step 1 — Verify PAT

```bash
# Find existing PAT (1Password / .env / keychain)
security find-generic-password -s "GITHUB_PAT" 2>/dev/null | head -5
echo $GITHUB_PERSONAL_ACCESS_TOKEN | head -c 10
# se vuoto, generare nuovo via https://github.com/settings/tokens/new
# scope: repo + read:org + workflow + (read:packages se serve)
```

Salva PAT in env var per Claude Code:

```bash
# in ~/.zshenv (per non-interactive shells):
export GITHUB_PERSONAL_ACCESS_TOKEN="ghp_xxxx"
# o usa keychain:
security add-generic-password -a "$USER" -s "GITHUB_PAT" -w "ghp_xxxx"
```

### Step 2 — Install via Docker (preferred per Nimbalyz)

```bash
claude mcp add github -- docker run -i --rm \
  -e GITHUB_PERSONAL_ACCESS_TOKEN \
  ghcr.io/github/github-mcp-server
```

Alternative npm (se Docker indisponibile):

```bash
claude mcp add github -- npx -y @modelcontextprotocol/server-github
```

### Step 3 — Verify Docker availability

```bash
docker --version
docker pull ghcr.io/github/github-mcp-server:latest
# pre-warm image
```

Se Docker non installato: skip Step 2 Docker, use npx.

```bash
# GitHub MCP vs gh CLI

## Use `mcp__github__*` (MCP) per:
- PR view/list/checks (strutturato, no jq)
- Issue search semantic
- Workflow runs status check
- Long-running session PR-heavy (caching MCP-side)

## Use `gh` CLI Bash per:
- `gh pr create` (MCP non supporta write?)
- `gh pr merge` (verifica MCP support)
- `gh auth login` (interactive)
- `gh api custom-endpoint` (per endpoint non in MCP)
- Multi-step pipeline shell-friendly

## Tie-breaker

Read-heavy workflow → MCP
Write operation che richiede shell pipeline → CLI

**Anti-pattern**: ripetere `gh pr view 123 --json title` 10 volte in sessione → switch to MCP.
EOF
```

## Open questions

1. **Docker vs npm**: Docker version più aggiornato + sandboxed. NPM version più semplice. Default = Docker (richiede Docker Desktop install).
2. **PAT vs OAuth App**: PAT is simpler. OAuth App permission flow più sicuro long-term. Default = PAT (solo Antonello user).
3. **Write operation gating**: MCP fa `gh_pr_create`? Se sì, va con guardrails.py (T1.2) — block destructive PR ops?
4. **Multi-repo support**: Nuzantara è single repo (Balizero1987/Teman2) ma anche `Balizero1987/Subhi-private-handover`. PAT scope deve cover both.
