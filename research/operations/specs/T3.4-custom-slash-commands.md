# T3.4 — Custom slash commands

## Problem

Workflow Antonello ricorrenti che ripeto verbatim più volte/giorno:

1. **/verify <target>** — verifica empirical (file exists, command output, ecc.) PRIMA di citare
2. **/panel <topic>** — fan-out 4-LLM (Claude + Codex + Gemini + DeepSeek) per spec review
3. **/research <domain> <query>** — fan-out deep researcher (multi-LLM + NB)
4. **/scar <severity> <description>** — append cicatrix-scars.md entry strutturato
5. **/resume** — re-inject Mnemos handoff (T2.5) post-compact
6. **/dispatch-stat** — count subagent dispatches this session vs baseline

Custom slash commands rendono pattern routine, riducono token (no re-typing).

## Context

Anthropic format slash commands:

- File: `~/.claude/commands/<name>.md` con frontmatter + body
- Invoke: `/<name> <args>`
- Body è prompt che Claude esegue (può chiamare tools)

Esistenti già: `/loop`, `/help`, ecc. Verifica directory `~/.claude/commands/`.

## Acceptance criteria

- [ ] 6 commands file in `~/.claude/commands/`
- [ ] Each invocable via `/<name>` syntax

### Step 2 — Write /verify

Path: `~/.claude/commands/verify.md`

```markdown
---
name: verify
description: Empirical verification — file exists / command exit / value present. Anti-hallucination 2026-05-13.
---

# /verify $ARGUMENTS

Verifica empirica del target. Esegui adesso (NOT memoria/context).

Tipi target:

- File path → `ls -la $ARGS` + report exists/size/perm
- Command verbatim → execute + report exit code + first/last 10 lines stdout
- Value/string presence → grep
- Process name → ps aux | grep
- URL → curl -m 5 + HTTP status

Output formato:
```

VERIFY <target>:

- Status: PASS|FAIL|PARTIAL
- Evidence: <command output verbatim 1-line>
- Anomalie: <list>

```

Anti-hallucination rule: cite empirical solo da QUESTO tool call. Mai memoria buffer.
```

### Step 3 — Write /panel

Path: `~/.claude/commands/panel.md`

```markdown
---
name: panel
description: Fan-out spec review 4-LLM (Claude Opus + Codex GPT-5.5 + Gemini 3.1 Pro + DeepSeek V4 Pro). Pattern Antonello 2026-05-13.
---

# /panel $ARGUMENTS

Spec review parallel via 4 LLM. ARGUMENTS = topic or spec file path.

Step:

1. Carica spec content (Read se file path; else use $ARGUMENTS verbatim)
2. Fan-out parallel:
   - Codex: `codex exec --sandbox workspace-write --skip-git-repo-check < /dev/null "Review questa spec per architectural flaw, edge case, security: <spec>"`
   - Gemini: `gemini -m gemini-3.1-pro-preview -p "Review spec for long-context dependencies: <spec>"`
   - DeepSeek: API call con `reasoning_effort=high` "Devils-advocate this spec: <spec>"
   - NB-1 NotebookLM (se UUID known): `mcp__notebooklm-mcp__notebook_query notebook="<uuid>" query="<spec key concept>"`
3. Sintesi tabella convergente/divergente

Output:
```

| Panelist | Verdict         | Top concern |
| -------- | --------------- | ----------- | ---------- |
| Codex    | PASS            | FAIL        | <one-line> |
| Gemini   | PASS            | FAIL        | <one-line> |
| DeepSeek | PASS            | FAIL        | <one-line> |
| NB-1     | (if applicable) | <one-line>  |

Convergent: <list 3 issue dove tutti agree>
Divergent: <list dove discord>
Recommendation: <next step>

```

Costo: ~$0.01 DeepSeek + 0 altri. Wall-time ~2 min parallel.
```

### Step 4 — Write /research

Path: `~/.claude/commands/research.md`

```markdown
---
name: research
description: Deep research via deep-researcher subagent + NotebookLM bipolar verifier.
---

# /research $ARGUMENTS

Format: `/research <domain> <query>` where domain ∈ {property, visa, tax, hr, compliance, immigration, regulatory}.

Step:

1. Parse `$ARGUMENTS` → estrai domain + query
2. Dispatch `deep-researcher` subagent con domain + query
3. Verifica output: ≥400 parole, ≥3 fonti, checklist presente
4. Cross-check con NB rilevante (vedi reference_notebooklm_arsenal_full.md):
   - property → NB-5
   - visa → NB-2 o NB-INTEL-Immigration
   - tax → NB-3
   - hr → NB-4
   - regulatory → NB-INTEL family
5. Save: `~/Desktop/nuzantara/research/<domain>/YYYY-MM-DD-<slug>.md` con frontmatter
6. Append memory entry sotto `MEMORY_RESEARCH_CAPTURES.md`

If domain=property: anche push NB-5 via `mcp__notebooklm-mcp__source_add notebook="d9438180-5e63-4e2a-a473-6061101f6a8d" text="<body>"`.
```

### Step 7 — Write /dispatch-stat

Path: `~/.claude/commands/dispatch-stat.md`

```markdown
---
name: dispatch-stat
description: Count subagent dispatches this session vs baseline (diagnose orchestration decay).
---

# /dispatch-stat

Step:

1. Find current session transcript: `~/.claude/projects/<project-id>/<session>.jsonl`
2. Count Agent tool calls: `grep -c '"name":"Agent"' <file>`
3. Count Bash calls: `grep -c '"name":"Bash"' <file>`
4. Count Skill calls: `grep -c '"name":"Skill"' <file>`
5. Compute lines: `wc -l <file>`
6. Compute ratio: Agent / (Agent + Bash + Skill) \* 100

Output:
```

=== DISPATCH STAT this session ===
Lines: <N>
Agent dispatches: <X> (ratio <p>%)
Bash calls: <Y> (ratio <q>%)
Skill calls: <Z> (ratio <r>%)
Baseline pre-decay (sessione 18.5K lines 2026-05-16): Agent 61/X, Bash X/X, Skill X/X

Verdict:

- GREEN: Agent% within ±20% of baseline
- YELLOW: Agent% 50-80% of baseline → likely orchestration decay
- RED: Agent% <50% of baseline → critical, invoke memory rule

```

Trigger /dispatch-stat ogni 300 lines empirical (manually for now, automated T1.1 hook).
```

## Open questions

1. **Slash command vs skill**: Anthropic platform supporta entrambi. Skill: invocato via Skill tool. Slash: invocato via `/<name>` UI. Differenza pratica? Skill può essere chiamato programmaticamente da agenti, slash è user-facing only. Default: implementa come slash (commands/) per UX semplice.
2. **Arguments parsing**: `$ARGUMENTS` viene passato verbatim al body? Verifica syntax Anthropic.
3. **`/research` conflict con dispatch-orchestrator** (Federation Orchestrator già in CLAUDE.md): potenziale duplicato. Federation = auto, /research = manuale. OK coexist?
4. **`/scar` auto-commit**: rischio commit accidentale. Default: solo APPEND a file, no auto-commit. Antonello commit manually.
