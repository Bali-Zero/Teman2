# T1.3 — Memory rule `feedback_orchestration_first.md`

## Problem

Hook strutturali (T1.1) intercettano DOPO che il task è iniziato. Manca la regola _deliberativa_ a livello memory che dice **"come decidere"** quando arriva un nuovo task. La memoria cross-session è il livello dove le regole comportamentali vivono ed influenzano il modello.

## Context

Anthropic auto-memory system carica primi 200 righe di MEMORY.md + tutti i memory file linkati a SessionStart. Le regole tipo `feedback_*.md` sono lette come _system instructions_ — sono il livello canonical per "this is how Claude in Nuzantara behaves".

Esistenti rules che funzionano (cross-verified):

- `feedback_always_review_spec_with_4_llm.md` (2026-05-13) — Active, citato in workflow
- `lessons_hallucinating_tool_output_is_diabolical.md` (2026-05-13) — Active

Gap: nessuna regola per "task arrival → arsenale selection".

## Design

Memory file con:

1. Single clear rule (1-2 sentence)
2. Why (referenze empirical)
3. Trigger condizioni precise
4. Counter-pattern (cosa NON fare)
5. Linked memory pointers (`[[name]]`)

Linked in MEMORY.md sotto sezione "Workflow rules ⚠️ (load-bearing per Claude)".

## Implementation steps

### Step 1 — Crea memory file

```bash
cat > ~/.claude/projects/-Users-nuzantara-Desktop-nuzantara/memory/feedback_orchestration_first.md << 'EOF'
---
name: orchestration-first
description: Decisione arsenale BEFORE Bash quando task ha multi-step indipendenti, investigation, o refactor 3+ file
metadata:
  type: feedback
---

Quando arriva un nuovo task, prima di lanciare il primo tool call, dichiarare in 1 riga: **direct Bash / load skill / spawn subagent / call MCP** + perché quella scelta fitta il task.

**Why**: regression 2026-05-21 ha rivelato decay strutturale dell'arsenale awareness dopo ~500 righe transcript (subagent dispatch 8→0 in `d955ac4b`). Cause: Bash è il riflesso più diretto e visibile, gli altri path richiedono "decisione attiva". Senza preflight esplicito, default = Bash sempre.

**How to apply**:
1. Task = singolo step Bash-shaped (test, lint, status, grep singolo) → **direct Bash**
2. Task = multi-step ma sequenziale stretto (es. "fix typo in 3 file conosciuti") → **direct Bash**
3. Task = investigation con N+ percorsi paralleli (es. "trova tutti i caller di X attraverso 25-app monorepo") → **spawn subagent** (Explore o general-purpose)
4. Task = "review/audit/red-team" → **spawn subagent specializzato** (deep-researcher, devils-advocate, code-reviewer)
5. Task = "draft brand-compliant content" → **load skill** (`bali-zero-brand` family) + dispatch wr2-*/wr3-* agent
6. Task = "send WhatsApp / Vercel deploy / GA4 query" → **call MCP** (`nuzantara-mcp__send_whatsapp`, Vercel MCP, GA4 MCP)
7. Task = "ground-truth regulatory/tax/visa/property" → **call NotebookLM MCP** (`mcp__notebooklm-mcp__notebook_query`)

**Counter-pattern (cosa NON fare)**:
- ❌ Bash `grep -r` su tutto il monorepo quando subagent Explore farebbe lo stesso in context isolato
- ❌ Bash `curl whatsapp-api` quando esiste `mcp__nuzantara-mcp__send_whatsapp`
- ❌ "Verifico io leggendo i file" quando subagent deep-researcher è già esattamente per quello
- ❌ Skip skill `bali-zero-brand` e scrivere copy direttamente quando il task è brand-output

**Trigger reminders**:
- Hook T1.1 `dispatch_nudge.py` inietta system reminder quando >500 righe + zero subagent
- Se hook scatta = stop, leggi questa regola, scegli path appropriato

**See also**: [[feedback_always_review_spec_with_4_llm]], [[lessons_hallucinating_tool_output_is_diabolical]]
EOF
```
