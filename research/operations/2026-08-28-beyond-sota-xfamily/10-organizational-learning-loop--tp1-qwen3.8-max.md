## 0. TL;DR

The organism is already ahead of most agent systems because it converts incidents into budgeted, family-classified, partially executable memory; its biggest gap is that learning is still mostly textual and not measured by prevented recurrence.

Top-3 moves:

1. Turn scars into executable tripwires with recidiva counters, so every high-value scar has guilt/innocence tests and a measurable recurrence rate.
2. Build incident-replay `modus-bench` fixtures from real scars and AMENDMENTS misfires, measuring “prevention rate” instead of merely “lesson written.”
3. Create a MEMORY/doctrine budget and drift ledger for injected doctrine, including the three `CLAUDE.md` copies named in the mandate, so byte cost, staleness, and divergence are visible.

The loop should move from “scar recorded” to “scar proven prevented.”

## 1. How the organism does it today for THIS part

Every claim below cites a ground-pack path. Where a path is mentioned inside a ground-pack file but not itself provided, I mark it as referenced, not verified.

### 1.1 Scar capture is family-based, budgeted, and injected

`.claude/rules/cicatrix-superscar.md` is the organizational scar bridge. It states that roughly 99 cicatrici are grouped into 10 superscar families plus orphans, and that each family has a structural disease, early signal, structural antidote, and short member list (`.claude/rules/cicatrix-superscar.md`). It explicitly says the file is injected into every session and every subagent, and that any addition is paid by the whole fleet forever (`.claude/rules/cicatrix-superscar.md`).

The same file imposes a `≤14KB` budget and says it is armed by `scripts/tests/test_superscar_budget.py` (`.claude/rules/cicatrix-superscar.md`). The budget is not merely stylistic: the test file confirms a hard byte budget of 14,000 bytes and a completeness rule that every W-number token in the superscar must resolve to a heading in the scar corpus (`.claude/rules/cicatrix-superscar.md`; `scripts/tests/test_superscar_budget.py`).

The bridge also names executable antidotes per family, e.g. `scripts/lint_home_fork.py`, `scripts/pending_arms_report.py`, `scripts/secrets_permissions_audit.py`, `scripts/lint_plist_keepalive.py`, and `scripts/branch_graveyard_cleanup.sh::content_on_main()` (`.claude/rules/cicatrix-superscar.md`). These script paths are referenced by the bridge but are not all present in the ground pack; I treat their existence and behavior as referenced, not verified, except where the script itself is included below.

### 1.2 Retrieval is lexical, offline-first, and anti-substring

`scripts/scar_query.py` is the retrieval half of the superscar bridge. It performs zero-dependency lexical search over the scar corpus, with word-boundary matching, title-weighted scoring, AND/OR modes, family rendering, and list mode (`scripts/scar_query.py`). Its docstring explicitly rejects dependence on Qdrant, embeddings, or daemons because that would create an “Esiste ≠ Armato” guardian that dies on first use on some node (`scripts/scar_query.py`).

The search is deliberately word-boundary aware to avoid family #3 guard-over-match: the script says a query term must match on a token boundary so `ota` does not match `quota` (`scripts/scar_query.py`). This is a rare SOTA-like property: the retrieval tool explicitly learns from the organism’s own substring-trapping scar family.

### 1.3 The scar corpus has integrity guards

`scripts/tests/test_superscar_budget.py` does three important things:

1. It enforces the superscar byte budget.
2. It enforces completeness: every W-number token in the superscar must have a real heading in the active or archived scar corpus.
3. It enforces that the cicatrix files are ignored by Prettier, because Prettier once rewrote scar records and corrupted them (`scripts/tests/test_superscar_budget.py`).

The test docstring also records a boot-tax audit: the superscar file had grown to 73,854 bytes despite claiming to be a thin bridge, so the guard exists to catch relapse into carrying full trauma/antibody paragraphs in the bridge (`scripts/tests/test_superscar_budget.py`).

### 1.4 Scar numbering is treated as a concurrency problem

`scripts/lint_scar_number_collision.py` is an executable antidote for W-number collision. It explains that a W-number is only claimed when a PR opens and resolved when merged, so reading only `origin/main` can miss open-PR claims (`scripts/lint_scar_number_collision.py`). It computes the claim set as the union of `origin/main` headings and added headings in open PR diffs, detects collisions, and can print the next free number (`scripts/lint_scar_number_collision.py`).

The script also encodes traps learned from live incidents: numeric sort rather than lexical sort, open-PR claim inclusion, and heading parsing that tolerates emoji before W-numbers (`scripts/lint_scar_number_collision.py`). It supports offline fixtures so guilt/innocence tests can be real subprocess runs (`scripts/lint_scar_number_collision.py`).

### 1.5 The action ledger is a pure signaler with strict classes

`scripts/pending_arms_report.py` reads the `PENDING-ARMS.md` ledger (referenced, not provided in the pack) and classifies entries into TECH-DEBT, FIREBREAK, NATURAL-WAIT, OPERATOR-GATED, PHANTOM-OPERATOR, and MALFORMED (`scripts/pending_arms_report.py`). It is explicitly pure: it never writes, edits, or mutates anything; its only control-flow effect is its exit code under strict modes (`scripts/pending_arms_report.py`).

The script contains a large amount of learned policy:

- Overdue TECH-DEBT is age ≥2 days at day precision (`scripts/pending_arms_report.py`).
- `operator` ownership is only legitimate for declared true-operator categories such as physical, GUI, TCC, consent, secret, control-plane, and business (`scripts/pending_arms_report.py`).
- Undeclared operator ownership is PHANTOM-OPERATOR and fails strict checks regardless of age (`scripts/pending_arms_report.py`).
- A malformed line, including stray conflict markers, is treated as more untrustworthy than a phantom line (`scripts/pending_arms_report.py`).
- A `--ref` mode reads the ledger from a git ref to avoid acting on a deliberately stale local checkout (`scripts/pending_arms_report.py`).

This is organizational memory with operational teeth: the ledger is not merely prose; it is parsed, classified, aged, and gated.

### 3.1 The five that matter most for this organism

**Reflexion / Self-Refine / ExpeL.** These establish that verbal lessons can improve future behavior, but they also expose the weakness: lessons are only as good as the retrieval and verification context around them. The organism already has richer lessons than most because its scars have family, disease, early signal, and antidote. The missing step is systematic measurement: did the lesson prevent the next incident?

**Voyager / Agent Workflow Memory.** These matter because the organism already has “executable antidotes” named in the superscar bridge. The SOTA move is not to store prose antidotes but to promote them into tested, reusable, discoverable skills with usage evidence. The organism is close to this, but the ground pack does not show a skill promotion pipeline.

**MemGPT / Letta / Mem0 / Zep.** These matter for MEMORY index budget. The organism’s current budget is static: bytes and completeness. SOTA memory systems add hierarchy, decay, consolidation, and temporal lineage. The organism can go beyond SOTA by combining its static budget with utility accounting: which injected bytes actually prevent scars?

**SWE-bench.** This matters for `modus-bench`. Generic agent benchmarks are less useful than an organism-specific benchmark built from its own incidents. The organism already has the raw material: W-numbers, AMENDMENTS entries, and ledger defects. The next step is replayable fixtures with prevention scores.

**SRE postmortems / DORA.** These matter because the organism is not just an agent; it is an operations organism. The best human organizations learn through blameless incident review, action-item aging, and learning-culture metrics. `pending_arms_report.py` already embodies this better than most agent systems, but it needs recurrence metrics and closure evidence.

## 5. Beyond-SOTA recommendations

Ranked by estimated `(impact × confidence) / cost`, with process-adoption cost included. Gear legend: **1** = script/lint, **2** = workflow/eval, **3** = architectural change.

### Rank 1 — Scar-to-tripwire compiler with recidiva counters

**What.** Give each high-value W-scar a machine-readable tripwire block or sidecar manifest: family, status, executable check, guilt test, innocence test, recidiva count, last recurrence, and owner. A reporter aggregates coverage and fails when a superscar claims an executable antidote but no tripwire exists.

**Why it beats SOTA.** Most SOTA agent memory is prose or vector memory. This turns scars into executable assertions and recurrence metrics. It makes “lesson learned” falsifiable.

**Cost.** Low-medium. Start with top families only.

**Gear.** 2.

**Risk.** Overfitting to old scars; noisy tripwires; false confidence if tests are weak.

**Metric + measurement.** Percentage of top-20 scars with passing tripwires; recidiva count per family per 30 days; false-positive rate of tripwires in clean runs. Measurement: CI reporter plus periodic ledger snapshot.

**Kill criterion.** If fewer than 25% of top-20 scars can be encoded after 30 days, or false-positive rate exceeds 10%, stop and redesign the tripwire schema.

**First PR.** `scripts/scar_tripwire_report.py`, `scripts/tests/test_scar_tripwire_report.py`, fixture JSON. ≤400 net lines. Acceptance: fixture with missing tripwire exits non-zero; fixture with valid tripwire exits zero.

### Rank 2 — Incident-replay `modus-bench` / scar-bench

**What.** Build replayable fixtures from real incidents: W126/W128 number collision, superscar boot-tax relapse, phantom-operator ledger line, malformed conflict marker, AMENDMENTS JSON-string `UNKNOWN-DATE`, and refuter half-false approval. The bench runs current guards and reports prevention rate.

**Why it beats SOTA.** Generic benchmarks measure generic capability. An organism-specific incident-replay benchmark measures whether the organization actually learned its own history.

**Cost.** Medium. Fixtures can be built incrementally.

**Gear.** 3.

**Risk.** Fixture rot; accidental leakage of secrets or PII; false prevention claims if fixtures are too narrow.

**Metric + measurement.** Prevention rate: number of historical incidents still prevented by current controls. Regression count when a control change lowers prevention rate. Measurement: scheduled bench run with redacted fixtures.

**Kill criterion.** If more than 20% of fixtures require manual repair each month, or if fixtures cannot be redacted safely, pause and simplify.

**First PR.** `scripts/scar_bench_replay.py`, three fixture files, tests. ≤400 net lines. Acceptance: replay detects the known W-number collision fixture and exits non-zero when the collision lint is disabled or bypassed.

### Rank 3 — MEMORY/doctrine budget and drift ledger

**What.** Create a ledger for always-injected doctrine: superscar bridge, `CLAUDE.md` copies, skill indexes, MEMORY index files if present, and any other session-start file. For each artifact record bytes, approximate tokens, last modified date, owner, budget, declared purpose, and usage proxies such as citations in scars, AMENDMENTS, tests, or PR bodies. Add a drift check for declared copies.

**Why it beats SOTA.** Static byte budgets are already rare. Utility-aware budgeting goes beyond MemGPT-style paging by making organizational doctrine cost and drift visible without changing context-injection mechanics.

**Cost.** Medium. The first version can be read-only.

**Gear.** 2.

**Risk.** Usage proxies may mislead; doctrine owners may game citations; archive candidates may recur.

**Metric + measurement.** Injected bytes per session; doctrine drift count; archive candidate count; recurrence of archived lessons within 14 days. Measurement: weekly ledger report plus drift lint.

**Kill criterion.** If usage proxies cannot be collected after 30 days, or if archived doctrine recurs within 14 days more than once, revert to static budgeting only.

**First PR.** `scripts/memory_budget_ledger.py`, config manifest, tests. ≤400 net lines. Acceptance: ledger reads the superscar file, reports its byte size, and fails when a configured budget is exceeded.

### Rank 4 — Doctrine drift lint for the three `CLAUDE.md` copies

**What.** Because the ground pack does not provide the `CLAUDE.md` paths, first add a manifest listing canonical and derived doctrine copies. Then lint normalized differences, allowing declared overrides with reason and expiry. Unauthorized drift fails CI or produces a loud report.

**Why it beats SOTA.** Most file-based memory systems assume copies converge. This treats doctrine as distributed state with split-brain risk, like infrastructure configuration.

**Cost.** Low if the paths are known; medium if discovery is needed.

**Gear.** 1.

**Risk.** The three copies may not exist as described; legitimate local overrides may be noisy.

**Metric + measurement.** Drift incidents per month; mean time to detect drift; number of declared overrides expired without review.

**Kill criterion.** If the operator cannot supply the three paths, or if more than 30% of flagged drifts are legitimate undeclared overrides after two weeks, replace lint with manual review.

**First PR.** `scripts/doctrine_drift_lint.py`, `.claude/rules/doctrine.yml`, tests. ≤400 net lines. Acceptance: fixture with clean copies exits zero; fixture with unauthorized divergence exits non-zero.

### Rank 5 — Retrieval golden eval and optional semantic upgrade path

**What.** Build a golden query set from each superscar family, major recidiva, and high-value W-numbers. Measure recall@k and MRR for `scar_query.py`. Only after lexical recall is baselined, add an optional BM25/FTS5 or local embedding cache that remains offline and never becomes a hard dependency.

**Why it beats SOTA.** SOTA retrieval is often semantic but fragile. The organism can keep its offline-first guarantee while proving retrieval quality. That is stronger than most vector-memory systems because the fallback is tested.

**Cost.** Medium.

**Gear.** 2.

**Risk.** Golden set overfitting; semantic layer introducing daemon dependency; retrieval improvement not translating to prevention.

**Metric + measurement.** Recall@5, recall@10, MRR, no-hit rate, startup failure rate in offline mode. Measurement: test suite and fixture corpus.

**Kill criterion.** If a new retrieval mode does not improve recall by at least 5% over lexical baseline, or if it fails offline startup, do not adopt it.

**First PR.** `scripts/scar_query_eval.py`, golden query JSON, tests. ≤400 net lines. Acceptance: baseline lexical recall is printed and pinned in a test.

### Rank 6 — AMENDMENTS lifecycle and evidence gate

**What.** Give each AMENDMENTS entry a stable ID and lifecycle: proposed, experiment, approved, merged, rejected, expired. Require evidence pointer and post-merge verification. A reporter ages amendments stuck without experiment or closure.

**Why it beats SOTA.** Most reflection systems append lessons forever. This makes loop misfires into experiments with closure, reducing lesson rot.

**Cost.** Low technically, medium culturally.

**Gear.** 1.

**Risk.** Bureaucracy; amendments may become performative; Zero gate may become bottleneck.

**Metric + measurement.** Median time from amendment proposal to closure; percentage with evidence; count of expired amendments; count of amendments later contradicted by recidiva.

**Kill criterion.** If median human overhead exceeds 20 minutes per amendment or more than 30% expire without review, simplify to append-only plus monthly review.

**First PR.** `scripts/amendments_report.py`, parser tests, fixture AMENDMENTS sample. ≤400 net lines. Acceptance: fixture amendment older than 30 days without evidence is flagged; closed amendment is not flagged.

### Rank 7 — Skill library promotion pipeline from executable antidotes

**What.** Turn verified antidotes into governed skills. Each skill has owner, tests, byte/token budget, usage counters, failure history, and promotion criteria. A skill cannot be promoted without guilt and innocence tests. Recidiva-linked skills get higher review bars.

**Why it beats SOTA.** Voyager-like skill libraries are powerful but often become junk drawers. This adds organizational governance: skills are born from scars, tested, budgeted, and deprecated.

**Cost.** High.

**Gear.** 3.

**Risk.** Premature abstraction; skills unused; maintenance overhead exceeds value.

**Metric + measurement.** Number of promoted skills used in real work; skill failure rate; time from scar to skill; deprecated skill recurrence.

**Kill criterion.** If fewer than five promoted skills are used within 60 days, abandon the pipeline and keep scripts as ordinary scripts.

**First PR.** `scripts/skill_promotion_report.py`, skill manifest schema, tests. ≤400 net lines. Acceptance: fixture skill without tests is blocked from promotion.

## 7. Needs-ruling

Only true human/operator items belong outside session-executable work. The organism’s own ledger parser already encodes useful categories (`scripts/pending_arms_report.py`).

1. **Business**: Zero GO for AMENDMENTS, changes to Legge 5 or equivalent governance rules, and decisions to arm historically broken automation where business risk is non-recoverable.
2. **Consent**: consent for external communication, account-level actions, or any action that changes rights/obligations outside the repo.
3. **Credential**: credential rotation, secret values, keychain access, or any operation requiring knowledge of a secret itself. Mechanisms may be scripted; values must not be.
4. **GUI**: interactive logins, macOS TCC grants, GitHub organization/repo settings requiring UI, browser CAPTCHAs, or external platform settings not exposed through authorized APIs.
5. **Physical**: hardware toggles, device pairing, phone-based approvals, or on-site actions.

Everything else—lints, reporters, fixtures, manifests, retrieval evals, budget ledgers—should remain session-executable.

## 8. Meta-pattern

The single defective belief generating most findings is:

> **“If a lesson is written down, the organization has learned it.”**

This belief produces the observed gaps:

- Scars become rich prose but not executable tripwires.
- AMENDMENTS become append-only history rather than closed experiments.
- Byte budgets protect context size but not prevention value.
- Doctrine copies are assumed aligned because they are textually similar.
- `modus-bench` is referenced as a consumer but not evidenced as a prevention metric.
- Skill libraries remain possible but ungoverned.

The corrective principle is: **a lesson is not learned until a test, ledger, or metric proves the old failure is now less likely.**
