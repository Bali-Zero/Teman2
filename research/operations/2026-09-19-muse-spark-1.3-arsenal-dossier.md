## 6ter — Trial 4: Muse as proposer on a 50-entry public KBLI lot (2026-09-19)

Design (pre-registered in full before any Muse call, `PREREG.md`): 50 KBLI-2025 entries, seeded
draw (seed 20260919) from the 124 canonical records whose `intel_2026.whatChanged` names a
5-digit code; canonical rev f7cbfdda4c. Source: official KBLI 2020 table (Peraturan BPS 2/2020,
text layer). Vintage rule: entries are KBLI 2025, the source is KBLI 2020 -> only claims the
entry makes ABOUT KBLI 2020 are adjudicable; a 2025 code flagged merely for being absent from
KBLI 2020 is a vintage trap and counts WRONG. Rubric: a proposal is RIGHT only if the field
exists, `valore_attuale` is a verbatim substring of that field, and (when required by the defect
type) `citazione_verbatim_della_fonte` is a verbatim substring of the source block — paraphrase
does not count. Threshold: right/all >= 90%. Public KBLI data only; no client data, CRM,
WhatsApp or intake reached Muse.

10 `muse exec` calls (5 entries each, `--model muse-spark-1.3`, scrubbed env, fresh empty dir),
`run.model.configured` and `run.terminal.completed` asserted 10/10, exit 0, 52-131 s/call.
Verifier: Kimi K3 on flagged entries only (9 calls). Final adjudication: Claude, against the
official BPS 2020->2025 crosswalk (`src/xwalk.json`).

| Measure | Value |
|---|---|
| Proposals | 52, on 32 of 50 entries |
| Mechanical checks (field exists / value verbatim / citation verbatim) | 52/52/52 |
| RIGHT, strict (any verifier says wrong -> wrong) | **48/52 = 92.3%** (threshold 90%, passed) |
| RIGHT, Claude adjudication (truncated-title residue accepted per PREREG) | 50/52 = 96.2% |
| Vintage traps fallen into | 0 of 5 |
| Recall vs. Claude's blind pre-registered list | substantive 10/15 · format residue 16/18 entries |

**The 4 not-right (strict):** b09-1 (69103) wrongly proposed dropping 69109 from
`bps_2020_ancestors` on title dissimilarity — the official crosswalk (lampiran 10, p.405) lists
69109 as an ancestor. b10-1 (85574) duplicate/mislabel: "completely new code" is literally true
of the number, the real defect is the co-proposed b10-2, which is right. b03-1, b03-3 (07221,
07229): "(Title...)" ellipsis flagged as format residue — Kimi calls it ordinary shortening and
accepted the identical b02-5; disputed, counted wrong in the strict figure only.

**Verifier lesson:** Kimi K3 also missed b09-1 — it lacked the BPS crosswalk row in its own
prompt, so a verifier without the crosswalk cannot catch this class of error. Both the proposer
and the verifier prompt must carry the crosswalk row on every future lot.

**Confirmed canonical defects, by code (20 substantive) — NOT cured here:** wrong 2020
predecessor 10113, 10301, 77210, 46451; false "unchanged from 2020" 64910, 66161; false "new /
did not exist" 71203, 74191, 85574, 62110, 62201; wrong 2020 glosses 56101, 56400; misleading
"same activity" on merges/splits 01498, 01615, 01700, 01272, 47909. A cure belongs to the
`scripts/kbli_filiera` compilers and needs the owner's explicit ok before any PROD write — this
trial only proposes and grades, it does not touch the canonical.

**Weak points:** recall is partial — missed 10304, 10309 (own 2025 code named as a 2020 source),
46411, 65121 (renumbered vs. unchanged), 85571 ("78421 (2017)"), residue on 01116/01121; one
batch (b03) wrote a `valore_fonte` note in Italian inside an English artifact (same leak as Trial
1); `valore_fonte` is sometimes a paraphrase — only the citation field is reliably verbatim,
graders must key on the citation, not the value note.

**Decision:** threshold met -> proceed lot by lot; both proposer and verifier prompts must carry
the BPS crosswalk row. Public KBLI data only — no client data, CRM, WhatsApp or intake was sent
to Muse. Artifacts (prompts, raw responses, grading) live outside the repo at
`~/.agent/research/muse-spark-2026-09-19/trial4/`.
