# Merge-OS v2 — the submission system, rewritten after refutation

> **Status: SPEC, ready for wave-by-wave arming.** v1 (Cowork-M5 draft, same day) was refuted by
> two cross-family seats — Codex sol found the v1 plan unarmable in every wave; Qwen 3.8 Max
> concurred on waves 1-2. This v2 folds in all 26 confirmed findings. The delta log (§6) records
> every change against v1 so the next reviewer attacks the CORRECTIONS, not the retired claims
> (W113: the replacement assertion is a new claim — this file points its next refuter at itself).

## 0. What survives from v1 (the sound core)

Three ideas survived both refuters untouched and remain the spine:

1. **The queue is the only serializer of global invariants.** Any invariant about the COMBINED
   state of the repo (migration-number uniqueness, monotonic registries, derived-state equality)
   is judged on `merge_group`, where the cumulative group IS the tree that lands. On the PR ref
   those checks are advisory. (Kills W40/W109b as a class.)
2. **The full proof is paid once.** Presubmit = slice; queue = full proof; post-merge = healing
   and nightly depth. (Google TAP / Meta / Chromium — the selection is a latency optimization,
   never a correctness boundary; the boundary is the queue.)
3. **Derived state is written by organs, not by hands.** What is a function of global state is
   regenerated by a bot — but through the queue, not past it (changed in v2, see §3).

Also unchanged: 4-ring model (R0 local pre-push → R1 PR → R2 merge_group → R3 post-merge),
per-key registries for NEW registries (Regola C), the required.d governance registry, the
"do not build" list (no commercial queue, no Graphite, no HEADGREEN, never re-promote the
aggregate CodeQL context, no timestamp migration renumbering — `migration_number` is INTEGER
32-bit, verified), the 7-rule agent PR contract, and the two-class priority model
(hotfix/revert jump-the-queue + FIFO, nothing else).

## 2. The two structural rewrites (what the refuters killed, and the new shape)

### 2.1 Ring-gating is fail-closed BY EVENT, and nothing is renamed

v1's fatal flaw (Codex F1): a single gating expression serving both events lets a classifier
that reads `pull_request.*` during a `merge_group` see empty inputs, skip every heavy job,
and land an untested group — because skipped = SUCCESS for required contexts, and the current
`test-summary` counts only `failure`/`cancelled` as red (its own env-block comment says exactly
this). The v2 shape:

- **On `merge_group`, heavy jobs run UNCONDITIONALLY.** The event check is first, structural,
  and not shared with any classifier logic:
  `if: github.event_name == 'merge_group' || <classifier says needed>`.
  The guilt corpus MUST include the merge_group case: *a merge_group run in which the classifier
  errors/returns empty still runs every heavy job*. Over-match on the PR side costs money;
  under-match on the queue side removes the authority — the corpus is written with failure
  pointing in the economic direction only on `pull_request`.
- **No context renames, no fan-in migration, no matrix sharding.** The 26 required contexts stay
  the individual job names; PR-side innocent skips satisfy them via skip=success (the sentinel
  semantics the repo already uses on 17+ workflows). v1's "fan-in as the single required
  context" contradicted its own "names don't change" (Codex F2) and matrix shards would rename
  `Backend Tests (Python)` out of the ruleset → every entry hangs "Expected". Any future ruleset
  topology change is a declared two-phase transition (add new context → observe → remove old),
  never a side effect.
- **Sharding is OUT of this spec.** xdist measured 1.16× (non-lever, 2026-07-17); matrix
  sharding spends 3-4 runner slots + ~4-5 min setup each — the resource this repo measured as
  binding. The suite-duration lever is the round-3 L3 route: `--durations=50` data (already
  committed, PR in flight) → attack the named slow tests. Revisit sharding only with a
  shadow-soak proposal + slot-budget math, after the flake regime exists.
- **Bot-authored PRs always run full R1.** Dependabot/Renovate/Actions bots have no R0 (no local
  pre-push) — the classifier is bypassed for any non-human author (`github.actor` allowlist of
  humans+agent-sessions, default = full). A lockfile bump that breaks imports must die on its
  own PR, not eject a 5-entry group (Codex F3, Qwen F2).
- **The judge is protected at the same tier as the workflows.** `scripts/prepush_classify.py`
  (already NEVER_INNOCENT for the local gate) is added to the hot-zone/CODEOWNERS-TIER1 set the
  moment it becomes the R1 judge: a PR must not be able to weaken the classifier that judges it
  (Codex F4 — `.github/workflows/` already has this protection; the classifier inherits it).
- **Kill switch, two layers with honest semantics:** repo var `MERGEOS_RING_GATING=off` flips
  new runs to today's behavior (unset/typo value ⇒ gating OFF — fail-open to the EXPENSIVE
  direction, never to skip); the documented drain procedure (pause queue, let in-flight groups
  finish, then flip) covers the in-flight window that a var flip cannot reach (Qwen F7, Codex F14).
  Rollback rule: a workflow job is never deleted while its context is required — two-phase, always.

### 2.2 The heal bot becomes a heal PR (nothing pushes past the queue)

v1's most dangerous omission (both refuters, independently): a bypass-actor bot pushing
`docs(sync): heal` commits straight to main **resets the merge queue's in-flight speculative
groups on every push** — at ~50 merges/day that is throughput collapse, plus concurrent-heal
races, plus an R2-untested commit on main (violating the design's own principle 1), plus every
push-triggered workflow firing on bot noise (Codex F5/F6/F7, Qwen F1/F8). v2 shape:

- **`docs-sync-heal` opens a PR and arms it** (`gh pr merge --auto`), exactly like any other
  actor. It passes R1+R2 like everyone; the queue serializes it; no bypass actor exists at all
  (Wave prerequisite deleted — Codex F12's ruleset-capability doubt becomes moot).
- **Debounce by construction:** at most ONE open heal PR at a time (the organ finds its previous
  PR by branch name and updates it instead of opening a second); the organ runs on a 15-min
  schedule on Pro, not per-merge; it no-ops when drift is zero.
- **Anti-loop by content identity, not block type:** the organ compares the HASH of the
  regenerated blocks against what is already on main/its open PR — a `docs_sync.py` that emits
  timestamps or unsorted output would otherwise heal forever (Qwen F8). Determinism of
  `docs_sync.py` output becomes a tested property (guilt: inject a timestamp → test red).
- The PR-side docs-sync check still downgrades as in v1: from byte-equality on global counts to
  "no hand edits inside generated blocks" + sentinel-conformity. W86 still dies — one wave later
  and through the front door.
- **Cost accounting:** a heal PR consumes one queue entry (~minutes of R2). At the measured
  drift rate (heal PRs expected: a few/day at most, only on docs-affecting merges) this is noise
  against the reset-storm it replaces. The weekly report counts heal PRs — if they exceed
  5/day, `docs_sync.py`'s inputs are the bug to fix, not the mechanism.

## 3. The rest of the doctrine (v1 ideas, hardened where hit)

- **Regola A with the diff SPECIFIED** (Qwen F6): on `merge_group`, migration-lint and the
  tg-gateway anti-regrowth lint diff `github.event.merge_group.head_sha` against its
  **merge-base with main** — the cumulative group tree, never the individual PR base. Honest
  attribution caveat (Codex F20): a colliding group FAILS and native GitHub does not bisect —
  the queue blocks the landing (the invariant holds) but naming the culprit PR remains a manual
  step aided by `mq why-red`. That is still strictly better than today, where the collision
  lands on main first.
- **Differential flake verdict with a valid control** (Codex F9): stage 2 re-runs failed tests
  against **the exact merge-base SHA of the failing group** (recorded from the event payload),
  never against moving `origin/main`; a group-interaction failure (A+B) is by definition
  differential (present with group, absent at base) and blocks — correct, since the GROUP is
  what would land. Stage-2 runs are budgeted: verdicts cached per (test, base-SHA); a test
  already confirmed flaky within 24h skips stage 2 (Qwen F11).
- **Quarantine with floors** (Codex F10): auto-quarantine requires minimum sample (≥5 failures,
  ≥50 runs), never touches tests markered `critical` (auth/payment/PII gates — those get a P0
  ledger line instead), caps total quarantined coverage at 2% of the suite, and every quarantine
  is a PR (visible, revertable), not a config mutation. 14-day SLA unchanged.
- **Security cadence decoupled from PR volume** (both refuters): security.yml gains
  `schedule: daily 03:17 WITA` as backstop; full scan stays in `merge_group`; the `push: main`
  duplicate is dropped only AFTER the daily schedule is live (order is load-bearing). Quiet-week
  CVE window: closed by construction.
- **Rearm bounded** (Codex F18): launchd-on-Pro trigger (GH scheduler measured unreliable)
  gains a retry ceiling (3 per entry), exponential backoff, and a circuit breaker (≥3 identical
  INFRA failures in 30 min ⇒ stop + P0 alert instead of requeue-storming a GitHub outage).
- **Adaptive window with a heartbeat** (Qwen F10, Codex F17): calm(5)/storm(2) driven by
  ejection class (INFRA ejections don't shrink the window — they trigger rearm; only CODE/FLAKE
  do); watcher writes a heartbeat; no heartbeat for 30 min ⇒ the window REMAINS WHERE IT IS and
  a P1 fires (a frozen window is a known state; a phantom controller is not). Manual lock
  respected: an operator-set value is never overwritten for 24h.
- **`mq.sh` absorbs the probe** — `scripts/queue_doctor.py` (merged this session, PR #3928) is
  wrapped as `mq status --all`; the action verbs (arm/requeue/dequeue/why-red/revert/handoff)
  land as v1 specified, with one correction (Codex F13): the "no push after arm" guarantee is
  not a preflight (temporally impossible) but a **post-arm watcher**: `mq arm` records the head
  SHA; the watcher dequeues + alerts if the branch head moves while queued.
- **`.secrets.baseline` joins the plan** (both refuters: named disease, no cure in v1): the
  round-3 L2 lever — detect-secrets diff-scoped on merge-base-enumerated files + a
  baseline-reconciliation wrapper (`--no-renames`; full scan forced when the baseline/triage
  rules/CI scripts are touched; weekly full-tree stays) — is Wave 3 of THIS plan. One plan, not
  two.

## 4. Wave plan v2 (measure → disarm traps → capacity → doctrine → flake)

**Wave 0 — safe subset + trap disarm (1-2 days).**
`mq.sh` v1 (status/why-red/handoff + queue_doctor wrap; arm/requeue with the post-arm watcher);
required.d snapshot (advisory); agent PR contract into CLAUDE.md; TG token rotation
(operator[credential], prerequisite for every alarm in this plan); path-filter cure done RIGHT:
remove top-level `paths:` from docs-sync.yml and migration-lint.yml, add job-level
change-detection + sentinel (adding `merge_group` alone leaves the PR context "Expected" forever
— Codex F12); **continuous conformance check**: a per-PR guard (not weekly — Qwen F9) that every
required context's workflow carries `merge_group` + no top-level `paths:`.
*Acceptance:* conformance guard green on a probe PR; `mq status` matches live queue state on 3
real PRs; post-arm watcher demonstrably dequeues a moved head (guilt test on a scratch PR).
*Rollback:* revert; no gate semantics changed.

**Wave 1 — the baseline organ (7 days, NO behavior change).**
Nightly probe (Pro) records: billed minutes/PR (Actions billing API, not wall-clock), queue
transit p50/p95, ejection rate BY CLASS (INFRA/CODE/FLAKE) and BY AUTHOR CLASS (human / agent /
bot — Codex F16's split), heal-drift frequency, slot utilization. Plus the L3 durations data
(already flowing once the round-3 PR merges).
*Acceptance:* 7 consecutive daily records; the −X% targets of later waves get their measured
denominators. Every later SLO becomes falsifiable here or does not exist.

**Wave 2 — capacity (week 2).**
Ring-gating per §2.1 (fail-closed by event, bots always-full, judge protected, two-layer kill
switch) on tests.yml first; security.yml only after its daily schedule is live; then the
`push: main` dedupe (pusher ≠ queue-bot) for both.
*Acceptance:* billed/PR down vs Wave-1 baseline (target set FROM the baseline, not from v1's
40%); zero pending-forever; CODE-ejection rate consistent with the global SLO (single coherent
threshold: ≤2%/week total, alarm at 1.5% — v1's 3%-vs-2% contradiction removed, Codex F16);
merge_group guilt case (classifier disabled ⇒ heavy jobs still ran) proven in CI.
*Rollback:* var flip + drain procedure; two-phase context rule.

**Wave 3 — doctrine (weeks 3-4).**
Regola A in queue (migration-lint + tg-gateway, diff specified §3); heal-as-PR organ (§2.2);
`.secrets.baseline` diff-scoping (L2); PR-side docs-sync downgrade.
*Acceptance:* guilt test — two scratch PRs with the same migration number: the group is blocked
before main (attribution manual, landing blocked); W86 innocence test — two router PRs merge
without touching docs-sync; heal PR observed opening, queueing, merging, and NOT reopening on
zero drift (content-hash anti-loop guilt test: injected timestamp ⇒ red).

**Wave 4 — flake + adaptivity (week 5+).**
Differential verdict (exact-base control, cached stage-2); quarantine with floors; bounded
rearm on launchd; calm/storm window with heartbeat; weekly merge-os report (p50/p95, ejections
by class, flake board, billed/PR, headroom, batch-size recommendation from measured pass-rate).
*Acceptance:* one full week where every INFRA ejection auto-rearmed within 15 min AND no
false-quarantine of a critical-markered test; the window observed shrinking and recovering
without a human.

Every wave is an autonomous PR series; stopping after any wave leaves the repo healthier than
before it. No wave requires queue downtime.

## 5. Do not build (unchanged from v1, plus two additions)

All v1 entries stand (no commercial/external queue below 150 PR/day sustained; no Graphite; no
HEADGREEN; the aggregate `CodeQL` context ban becomes a guilt-test; no timestamp migration
renumbering; no ML test selection at this scale). Added by refutation:

- **No matrix sharding of the backend suite** without a shadow-soak + slot-budget proposal that
  a refuter has passed — the latency win is real, the slot cost hits the measured binding
  constraint (both refuters, F3/F8).
- **No bypass actors on main, for anything.** The heal-as-PR mechanism removed the only claimed
  need; any future "just this one bot" proposal re-fights the whole §2.2 battle from zero.

## 7. Residual risks (declared, not hidden)

1. **Later red discovery for agent PRs** remains: an agent PR whose author skipped R0 discovers
   code-red in the queue. Bounded by the always-full bot rule + the coherent ≤2% ejection SLO
   measured per author class; retreat lever (classifier tri-state skip/targeted/full) specified
   and armed only by baseline data.
2. **Heal-as-PR latency**: derived docs lag main by up to ~1 queue transit + 15-min schedule.
   Accepted: W86's cure was correctness of the gate, not freshness of the docs.
3. **The baseline organ is itself a reporter** (family #2 risk): its 7 daily records are the
   acceptance artifact — a missing record is a red acceptance, never "assume linear".
4. **Group-interaction blocks stay manual to attribute** (native queue has no bisection). `mq
   why-red` narrows it; if measured attribution cost exceeds ~2 operator-interventions/week,
   the bisection organ (v1 Wave-3 option) gets its own spec + refute round.
5. **This v2 has not itself been refuted post-rewrite.** The delta log (§6) is the refuter's
   target map: the corrections are new claims (W113). One cross-family pass on §2 and §4 before
   Wave 2 arms; Waves 0-1 are observational/trap-disarm and may arm after ordinary R1 review.
