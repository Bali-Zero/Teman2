# Beyond-SOTA 13/13 — Security, secrets & PII engineering

## 0. TL;DR

- **Position in one sentence:** AHEAD of SOTA on the PII output boundary (Law 2), insider/RBAC model and incident memory; AT SOTA on repo scanning, prompt-injection posture and supply chain; BEHIND on everything that trusts the machine as one pool — secrets at rest, env inheritance to three LLM vendors' CLIs, sandbox defaults, network policy, token lifecycle.
- **Biggest gap:** the *process-environment channel*. Every `codex`/`agy`/`kimi` child inherits the session env (PAT + tokens, measured 2026-08-18; one confirmed vendor-bound print), while Shai-Hulud proved env-harvesting is the era's dominant real attack — and this channel has zero antidotes, only memories.
- **Top-3 moves:** (1) **R1 Seat Broker** — exec-time, per-seat minimal env for every external LLM dispatch (op-run semantics × CaMeL capabilities × the org's own registries; metric: secret-shaped env names per child ≥3→1). (2) **R3 tailnet apply+drift receptor** — one operator GUI session arms the already-written deny-by-default policy; a receptor then diffs the ENFORCED netmap, not the file. (3) **R4 rotation SLA** — a clock on `operator[secret]` rows: one credential has been public and unrotated for ~7 months.
- The meta-disease (§8): Law 6's *availability* stance silently inherited as a *security* model — "the machine is the trust boundary." The cure across R1/R2/R6/R7 is one move: shrink the trust unit from machine to process/seat.

## 1. How Nuzantara does it today

All paths below were verified on disk in this session (worktree `research-beyond-sota-0828`, HEAD = main at launch). This lane reports on mechanisms only; no secret file was opened, no value printed.

**1.1 The constitutional layer: Law 2 output boundary.** `SYMBIOSIS.md` Legge 2 (verified: the derogation block at `SYMBIOSIS.md:242-253`) defines the frontier not as "no LLM sees operational context" but as *no output, memory, skill, report, log, alert, or shared artifact transcribes client PII/OSINT in cleartext* — processing may use context; outputs speak in `client_id`/hash/placeholder. Exactly **one named exception** exists (S7 yield digest → WhatsApp to the already-assigned team member, payload limited to name+initial, `client_id`, deadline), and the text explicitly forbids the "the data already travels there" argument from ever generalizing it. `CLAUDE.md:282` (§14) restates the boundary with the UU PDP Art. 35-39 grounding and marks the chat-gateway Art. 56 fail-closed as *required conduct, not yet implemented state* — an honest open gap held in PENDING-ARMS. Legal posture lives in `docs/UU_PDP_COMPLIANCE_REPORT.md` (UU 27/2022 + Constitutional Court 151/2024 + BSSN Reg. 1/2024) and `docs/PDP_COMPLIANCE_PLAN.md` (DPO mandatory post-CC-151/2024; CIRT registration; NPWP 16-digit regex).

**1.2 Secrets at rest.** Canonical store is per-machine `~/.nuzantara-secrets.env`, 0600, flat `NAME=value` (`docs/runbooks/secret-rotation.md`, born from the 2026-07-18 Kimi S2 scar: a rotated key is rotated only when *every consumer* reads the new value). The auditor is `scripts/secrets_permissions_audit.py` — superscar-#4 family auditor that matches by **name/path pattern only**, never opens contents (deliberate anti-exfil invariant), covers `.bak`/`.orig`/`~` inheritance, and exits 2 on a BLIND scan (zero files traversed ⇒ never certify "clean" — W84 discipline). Its measured blind spot is structural and ledgered: generic-named tool configs (`~/.qwen/settings.json` held a 113-char API key at 0644, invisible to the auditor because `settings.json` doesn't look like a credential — PENDING-ARMS row opened 2026-08-22).

**1.3 Secrets in the public repo.** The repo is public and does not rewrite history. Pre-commit runs `detect-secrets` v1.5.0 with `.secrets.baseline` (`.pre-commit-config.yaml:2-6`) plus **custom gap-filling checks written after measured detector misses**: detect-secrets ships no detector for Telegram `<bot-id>:AA<33>` tokens (comment at `.pre-commit-config.yaml:89-91` — "that is how @Balizerobot's LIVE token reached the public repo") nor for `GOCSPX-` Google client secrets. Doctrine is **revocation-first**: `CLAUDE.md:275` records the burned `@Balizerobot` token that *cannot* be revoked (BotFather answers only to a lost account) and must be treated as adversary-held forever; `CLAUDE.md:265` records the rotated+revoked Brevo admin key. Two measured reference memories harden the doctrine: squash-merge does NOT unpublish a leaked commit (`refs/pull/N/head` stays fetchable by anyone, measured 2026-08-21 on the sibling repo), and the GitHub secret-scanning API returns the `.secret` field in cleartext on every GET — *listing alerts is printing the secrets* (measured 22/22 on the sibling repo; safe probe = ask for field existence, never the field). Exposure handling uses **sha256 fingerprints, never values** (e.g. `scripts/lint_google_oauth_credentials.py`, per its PENDING-ARMS row).

**1.4 LLM credentials & OAuth seats.** Six Claude OAuth seats (`CLAUDE_CODE_OAUTH_TOKEN_1..6`, 5 MAX + 1 Team premium; `CLAUDE.md` seat table) live exported in the secrets env. The slot↔account map is **documentary, not measurable**: a token carries no identity (`claude auth status` returns only `authMethod: oauth_token`), so a token on a closed slot is a silently dead lane (W104-class), and quota introspection needs the interactive Keychain credential (`user:profile` scope — long-lived tokens get 403). The Anthropic **paid path is banned** (`CLAUDE.md:155`): CLI-only via `claude` + OAuth; `apps/backend-rag/backend/llm/claude_oauth_client.py` is the sanctioned substitute (subprocess to `claude -p`, "Never import this from a module that also imports `anthropic`"), and the ban has a CI consumer: `.github/workflows/catE-sovereignty-lint.yml` (born from the 2026-06-11 guardian-of-guardians audit — the lint existed but had no CI consumer, W64 "exists ≠ armed") with a 16-line baseline file. Gemini-side, `infra/llm-credentials/declared.json` is an allowlist of credentials permitted to call the production Google project — currently **1 declared credential**, recorded as `{declared, label, owner, sha256_16}` — fingerprint-not-value again, consumed by `scripts/llm_provider_reconcile.py`.

**1.5 The environment-inheritance surface (the open wound).** Memory `discovery_external_llm_clis_inherit_secrets_from_the_session_env_2026_08_18`: every `codex exec` (OpenAI), `agy` (Google), `kimi` (Moonshot) child inherits the session env, which measurably contains `GITHUB_PERSONAL_ACCESS_TOKEN` and `CLAUDE_CODE_MESSAGING_TOKEN`; a Codex refuter *spontaneously reported* having printed a Telegram token read via `launchctl` into its own output — i.e., to the vendor. **1.6 Hooks as backstop.** Three-tier guardrails client (`~/.claude/hooks/guardrails-client.sh`): daemon UNIX socket (~5 ms) → inline static evaluator (`guardrails-static.py`, byte-identical pattern sets, anchored destructive-SQL regexes) → **fail-closed** log+exit-1; emergency bypass needs two keys (env var + operator-presence flag file). `infra/claude-hooks/host_boundary.py` blocks mutating writes to the control plane (`~/.claude/`), credentials (`~/.ssh`, `~/.aws`, secret dotfiles) and decisions dir — the guardian of the phase switch exists *before* the switch, so an agent cannot disarm its own guardrails; reads of secret files emit a non-blocking WARN (visibility, not prevention). `infra/claude-hooks/data_plane_guard.py` blocks interactive hand-edits of curated datasets via a registry (`data-plane-registry.json`), covering Edit/Write/Bash **and Monitor** ("the SAME shell channel with different scheduling"). `~/.claude/scripts/prompt-injection-scan.sh` scans PostToolUse output for injection patterns and surfaces a `systemMessage` — **non-blocking by design** (surface suspicion; the model decides). Principle codified in `CLAUDE.md` §7: "if a critical rule is violable, write a hook."

**1.7 RBAC & code-review trust.** `.github/CODEOWNERS` (201 lines) implements tiers with an explicit threat model in its header — *"Agentic workflow injection … is the primary threat"* — Tier-1 on `/.github/workflows/`, `dependabot.yml`, `CODEOWNERS` itself, and the unattended Codex autofix trust boundary (its runtime lib, selector, pinned pre-push bundle and their executable proofs). **1.8 Sandboxing & supply chain.** Codex runs `--sandbox read-only|workspace-write` only, never `--dangerously-bypass` (`CLAUDE.md` §5). **The five that matter most.** (1) **Shai-Hulud** is the survey's center of gravity: the dominant real-world attack of 2025 did not crack a vault — it read `env` and ran an off-the-shelf secret scanner *as the attacker*, inside processes the victim launched voluntarily. ## 5. Beyond-SOTA recommendations (ranked by impact × confidence / cost)

**R1 — Seat Broker: exec-time, per-seat minimal environments for every external LLM dispatch.**
*What:* `scripts/with_seat.sh <seat> -- <cmd>`: build the child env from `env -i` + a functional allowlist (PATH, HOME, LANG, TERM) + ONLY the credentials that seat is declared to need, read at exec time from Keychain (`security find-generic-password`) or an `age`-encrypted store — never from the exported session pool. Declared per seat in a registry extending the existing `infra/llm-credentials/declared.json` pattern. A PreToolUse lint (same contract as `data_plane_guard.py`) WARNs on bare `codex exec|agy|kimi` invocations not wrapped, then graduates to BLOCK once the fleet's wrappers are migrated.
*Why beyond SOTA:* 1Password's `op run` [10] scopes secrets to a child but injects *the same set everywhere*; CaMeL [3] scopes capabilities but needs an interpreter; nobody surveyed does **per-vendor-LLM credential minimization** — and Shai-Hulud [11] proves env harvesting is the era's dominant real attack. This composes op-run semantics × CaMeL's capability idea × the org's own declared-registry + hooks-as-backstop asymmetry.
*Cost:* ~1 session (Gear 2), zero spend. *Risk:* family #1 (a HOME-fork wrapper diverging — antidote: ship in repo + `declared-pairs.json` entry) and #3 (the lint over/under-matching dispatch forms — guilt+innocence fixtures mandatory).
*Metric:* count of `*(TOKEN|KEY|SECRET|PASSWORD)*` env names visible to a probe child. Baseline measured 2026-08-18: ≥3 in an interactive session, the full secrets file in sourced cron wrappers; target: exactly the seat's own (1) per dispatch. Measurement: the test itself (`env | grep -cE ...` in the child, names only).
*Kill criterion:* if two weeks of WARN telemetry shows wrappers breaking on env starvation faster than they can be fixed, freeze at WARN and re-scope.
*First PR:* below (§6, PR-1).

**R2 — The trifecta ledger: Willison's lethal trifecta as a CI-linted invariant per lane.**
*What:* a registry (`infra/trifecta/lanes.json`) declaring, for every agent lane/daemon/MCP surface: `private_data`, `untrusted_content`, `egress` (booleans + evidence pointer each). A lint fails CI when any lane holds all three without a named, verified mitigation (e.g. "egress = Telegram digest, payload gated by yield PII gate"). Seeded from what the org already declares: organs registry, `FLEET_TOPOLOGY.json`, `.mcp.json`, `~/.claude/agents/`.
*Why beyond SOTA:* Willison states the trifecta as advice [4]; Google enforces origin sets inside one product [5]; OWASP Agentic lists the risks [2]. **No surveyed system computes and enforces the trifecta across a heterogeneous fleet as a repo lint.** The org's asymmetry: it is the rare shop whose lanes are ALREADY declared as data.
*Cost:* 1-2 sessions (Gear 2-3: the census is the work). *Risk:* #3 (a registry that describes rather than measures becomes theater — every boolean needs an evidence pointer; stale entries caught by pairing with the organs-registry census) .
*Metric:* # lanes with an unmitigated full trifecta. Baseline: unknown (the census IS the baseline — candidate examples the scars already name: a refuter with web output + session env; the WA bot with client rows + inbound messages + outbound sends). Target: 0 unmitigated.
*Kill criterion:* if the census shows <3 full-trifecta lanes, downgrade to a doc, not a lint.

**R3 — Tailnet drift receptor: diff the ENFORCED packet filter, not the intended file.**
*What:* apply `policy.hujson` (existing, `operator[GUI]`) and add `scripts/tailnet_policy_drift.py` to proprioception: read `tailscale status --json`/`debug netmap` and fail when the live filter is allow-all or diverges from the policy's declared shape (e.g. writable serve endpoints, untagged nodes).
*Why beyond SOTA:* policy-as-code is standard [14]; **diffing the runtime netmap against the repo policy continuously is not** — shops diff the ACL file, which is exactly how "esiste ≠ armato" (family #2) reaches the network layer. The org's proprioception bus is the asymmetry that makes it one small receptor.
*Cost:* ~200 lines (Gear 2) + one operator GUI session. *Risk:* #2 itself (a receptor that reads the wrong key — the probe must parse the filter rules, not the policy file's presence).
*Metric:* proprioception boundary `tailnet_policy`: today would report DIVERGED (measured allow-all vs proposed deny-by-default + the `ttyd -W` serve); target GREEN before any team device joins. Before/after: 1 unauthenticated writable shell exposed tailnet-wide → 0.
*Kill criterion:* none — this is the precondition the team-expansion plan already declares.

**R4 — Rotation SLA: give the `operator[secret]` class a clock and one ceremony.**

*Why beyond SOTA:* revocation-first is the org's own doctrine; the industry norm after a leak is rotate-immediately [7][8]. *Cost:* Gear 1-2, ~150 lines. *Risk:* #2 (the digest lane itself must be provably armed — send through the healthchecked Telegram path).

**R5 — Law-2 linter: the output boundary as a local, executable gate on the organism's own artifacts.**

*Why beyond SOTA:* Presidio exists for *customer data pipelines*; nobody surveyed lints **the agent's own writing** (memories, incident reports, research) against a constitutional output boundary. The org is the only surveyed system with such a boundary to lint. The PII-history-purge PENDING-ARMS row proves violations today are found by hand, after publication.

**R6 — Recorder receptor: treat "something is watching the screen" as a monitored boundary.**

*Cost:* Gear 1, <100 lines. *Risk:* #3 (signature list under-matching new recorders — the receptor reports NEW long-lived children of AI vendor apps generically, not a name list).

**R7 — Env-canary lattice: make the invisible exfil channel measurable.**

*Metric:* canary fire count (expected 0; any fire = measured breach with channel attribution); coverage: ≥3 channels instrumented (env, config, backup).
*Kill criterion:* if alert path cannot be made reliable (family #2), don't ship — a dead canary is worse than none.

## 8. §Meta-pattern (Gear 3)

**The single defective belief: "the machine is the trust boundary."** Law 6 (local sovereignty) is a *availability* stance — the organism lives on Zero's machines — but it has been silently inherited as a *security* model: everything inside one machine is one trust pool. Every scar in this lane is that belief leaking through a different channel: world-readable files (any local process may read), env inheritance (any child process may read — including three LLM vendors' CLIs), `launchctl` (any process may read other jobs' env), the screen (any granted app may read everything displayed), the tailnet (any node may reach any port, because every node "is Zero"), the FLY_API_TOKEN poisoning (whatever is in env is trusted over better credentials). Meanwhile the one boundary drawn at the right altitude — Law 2, on *outputs* — is the organism's strongest asset and the place it is genuinely ahead of the world. The correction is not more rules; it is moving the trust unit from **machine** to **process/seat** (R1, R2, R6, R7 are all this one move in four costumes).

Second-order pattern, honestly stated: **antidotes inherit the scope of the incident that birthed them.** The permissions auditor sees filenames because the wound was a filename; detect-secrets grew one detector per burned token class; the Telegram healthcheck covers the one lane that died. Each is real protection AND each scope-boundary became the next incident (0644 `settings.json`; GOCSPX; the 13 swallowed sends). The organism's own superscar language predicts this — famiglia #3, "the guard judges the form, not the entity" — applied to its *defenses*, not just its guards. Beyond-SOTA here means writing antidotes one abstraction level up: not "detect this token pattern" but "minimize what any child can see"; not "chmod this file" but "measure what fires when anything exfiltrates."
