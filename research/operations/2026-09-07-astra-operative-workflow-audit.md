# Nuzantara's operative workflow

## 1. Executive verdict

**Realign and enforce the workflow we already have. Do not create another workflow system now.** Nuzantara already combines an operator-directed development lifecycle, risk-based Gear classification, native Claude workflow execution, heterogeneous CLI seats, isolated worktrees, evidence artifacts, required GitHub checks, and documented continuity/closure procedures. These are not all equally enforced, and they do not yet form one uniformly governed mission runtime.

The strongest description of the current system is **an established operating method with several real enforcement paths and incomplete connections between them**. The new imperial/general hierarchy is a documented target and a partially built pilot. It is not the authority currently consumed throughout the repository, HOME configuration, CI and every native runtime.

Five findings determine the recommendation:

1. **Dynamic Workflows are already part of the method and have actually run.** `/workflow` explicitly calls itself the parallel arm of `/modus`; versioned templates exist. Fable's proposed universal `model:` rule is already written. The unresolved question is coverage of the actual launch path, not whether to write the rule again. [R: `.claude/skills/workflow/SKILL.md:12–17,35–56`; `infra/workflows/README.md:1–62`.]
2. **The largest cited run did not execute 113 Fable workers.** Its 113 native agent records all identify Opus; the script explicitly selects Opus. It comprised six readers, 106 refuters and one synthesizer, with a reconstructed peak of eight concurrent agents. The multiplicative verification structure deserves scrutiny, but attribution to the imperial default is false. [N1, below.]
3. **The reported 11,768,195 tokens are not cumulative model consumption.** They equal the sum of the workflow's per-agent display counters. Installed runtime code replaces an agent's token count with its latest request usage; it does not sum every request. Separately deduplicated native records contain 9,822 new input tokens, 11,956,163 cache-write tokens, 345,717,059 cache-read tokens and 2,027,403 output tokens. These are observed, provisional local counters, not an invoice, quota measurement or justified savings estimate. [N1; installed binary observations B1.]
4. **The old authority model still loads.** Roster, fleet topology and skills retain permanent Opus final-review prescriptions and historic exclusion of Fable. Zero's current ruling supersedes those prescriptions as intent; it does not change their bytes or consumers. A pilot candidate removes part of this conflict and adds reviewer-independence validation, but is unmerged, ungraded in its retained handoff, and initially NOTICE-only. [R: `MODEL_ROSTER.md:31–36,259–264`; `FLEET_TOPOLOGY.json`; C1.]
5. **The main missing capability is a dependable transition between existing parts.** A reserved slot must not be allocated twice; a completed artifact must reach its next owner; a review must refer to the current artifact and an independent contributor identity; a local stop must not be represented as confirmed remote cancellation. A new graph library would not establish any of these facts by itself.

## 2. The current route: request to verified closure

There is no single mandatory executable entrypoint for every request. An interactive development session, a product campaign, a scheduled organism cell, a native workflow and an external builder have related but different callers. Treating the cell event bus as the developer-session scheduler, or treating a native workflow as the entire shipping lifecycle, merges distinct systems.

### 2.1 What the Gear machinery actually does

The session chooses a provisional Gear. The linter computes a lower bound from changed paths and, when available, Git numstat. The headline size is **added plus deleted lines after exclusions**, not net file growth. Hot-zone paths floor at 3. Ordinary counted churn floors at 2 from 400 lines and at 3 from 1,828. Generated/vendor/fixture/lock/binary exclusions matter. Missing numstat degrades to path-only classification. A narrow first-party Actions-version-only patch exemption exists; this is not a general CI-file exemption. [R: `scripts/evidence_pack_lint.py:430–446,811–923,945–1090`.]

| Mechanism | Blocking behavior now | What it does not establish |
| --- | --- | --- |
| Declared Gear below computed floor | Linter error; required CI recomputes from base-owned code. | Runtime task risk before a diff exists; all semantic risks through a finite path list. |
| Gear ceiling | For docs-like/small diffs, declared Gear 3 plus a council or at least three graders can fail; nonempty `gear_override` changes this to a notice. Hot-zone floor wins. | A preventive limit on agent starts. A declared Gear 3 without those ceremony fields is not rejected by this ceiling. |
| Appetite | Missing appetite is allowed. Unmeasured spend notices. A declared, measured overrun fails without a textual acknowledgment; `appetite_exceeded` acknowledges it. | Live interruption, automatic suspension, defaults, trustworthy measurement or a provider quota limit. |
| Gear-3 council journal | Since September 2, normally requires at least two distinct qualifying review-seat labels. `seat_override` remains an explicit notice escape. | Conditional council selection from modus; actual model identity, independence, review quality or signed source provenance. |
| Build-lane diversity | Full linter requires a non-Anthropic build lane when there are at least two build lanes for Gear 2/3, with date-based enforcement. | An obligation to fill every rank/account; evidence that a declared lane actually built something. |
| Effort | Linter helper maps 1→medium, 2/3→xhigh. `seat_build.sh` separately caps Luna/Terra and restricts Sol xhigh/max to a declared Gear 3. | Equal behavior across native launches. The wrapper's Gear-2 default remains advisory, conflicting with the helper mapping. |

Anchors: R `scripts/evidence_pack_lint.py:1111–1243,1388–1418,1847–2051,2076–2174,2592–2671`; `scripts/seat_build.sh:153–220`.

**Actual CI coverage is narrower than the entire linter.** `harness-floor.yml` checks out the immutable base, resolves the PR's own brief/pack and compares the floor. Its full Evidence Pack validation and external verdict read are conditional on declared Gear 3; Gear below 3 exits that path. Therefore statements that every Gear-2 pack necessarily receives all full-linter checks in this required job are incorrect. Running the linter locally is another caller, not a substitute for required-path enforcement. [R: `.github/workflows/harness-floor.yml:268–274,636–717,824–889,1073–1147`.]

This is an observed live check, not merely YAML: [run 34057650399](https://github.com/Bali-Zero/Teman2/actions/runs/34057650399) completed floor calculation and took the no-brief/floor-1 path; [run 34056617558](https://github.com/Bali-Zero/Teman2/actions/runs/34056617558) reached and failed the Gear-3 verdict read. A lookup of the optional `HARNESS_ENFORCEMENT` repository variable returned 404; that response was not treated as proof of disabled enforcement. The completed steps demonstrate that those runs were not disabled.

### 2.2 There are several different kinds of budget

1. **Gear/appetite:** retrospective, self-reported PR accounting.
2. **Native Workflow output target:** installed `2.1.263` tool text describes a turn-shared output-token pool across the main loop and workflows. At the target, further `agent()` calls throw; already-running agents finish. This is a real start barrier, but not a hard cap on combined input/cache/output, external CLI descendants, or unavoidable in-flight overshoot. No target means no token-based stop from this mechanism. None of the four saved scripts contains a budget reference; their record schema does not prove whether a user turn target existed.
3. **Runtime cardinality:** workflow concurrency and total-agent caps constrain runaway breadth, not total cost; `workflowSizeGuideline` is advisory.
4. **CLI watchdog:** local deadline and process-group cleanup. It does not certify that the provider stopped or that remote usage ceased. [R: `scripts/lib/seat_watchdog.sh:7–40`.]
5. **Subscription usage snapshots:** routing information, explicitly not a work refusal rule in the existing roster. Stale or partial figures are not spendable headroom. [R: `MODEL_ROSTER.md:284–287`.]
6. **Mission admission requirement:** the existing adapter validator can reject a request whose required hard cap is unproved. Rejecting an unqualified capability is different from enforcing that capability. [R: `scripts/conductor/adapter_contracts.py:139–162`.]

B1: installed Claude binary SHA-256 `ef5d2909c8af49f31ab6d5487e90316777bc2fac170adfe8160716caa8aaf4f9`; bounded static inspections found the budget error at byte 171776278 and budget API text at 175611902. No workflow was executed to test it. The byte offsets identify this binary only, not a stable public API.

### The native capabilities we can actually rely on

Installed-version and public-documentation evidence should remain separate. B1 below confirms specific internals of this binary; public documentation describes the supported current contract. Neither authorizes a live experiment in this mandate.

**Workflows.** Current documentation specifies up to 16 concurrent workflow agents (possibly fewer by CPU), 1,000 cumulative agents per run and 4,096 items per parallel/pipeline call. Replay can reuse completed agents after resuming the same saved session; the first changed or failed call and later starts rerun. **Subagents and context.** Current Claude documentation describes three nesting layers by default, configurable through the relevant environment setting, and a separate default of 20 concurrent ordinary subagents. Fresh non-fork agents receive task, instructions and environment rather than the parent's full transcript; forked agents are an exception. Custom definitions can preload skills and constrain tools. Thus differentiated contexts are already a native building block: the missing work is concise role/task packets and appropriate capability scope, not a transcript-copying infrastructure. The old five-level sentence in modus is version-stale. [Official subagent documentation](https://code.claude.com/docs/en/sub-agents).

**Codex-native work.** Current documentation supports configurable subagent definitions, models, reasoning, skills and tools, with inherited sandbox defaults. `agents.max_threads` is a legacy alias for the documented concurrency setting. [Official Codex subagent configuration](https://learn.chatgpt.com/docs/agent-configuration/subagents).

**Cache.** Reusable content is an exact compatible prefix, including tools/system content. Models have separate caches; effort and other prompt-shaping settings can change the prefix, with documented product-specific exceptions. A shared family name is insufficient. Native workflow staggering improves the chance that a matching prefix is ready before followers start. It does not eliminate task input, repeated context reads or output cost. A different process alone does not prove a miss. [Official prompt-caching documentation](https://code.claude.com/docs/en/prompt-caching).

**Messages.** Native cross-session communication uses local session discovery and transports; remote-control routes have a different boundary. Peer messages do not acquire user authority or consent. ## 6. Meta-pattern: substituting a declaration for a state transition

The recurring error is **assuming that naming the intended state creates it**:

- A role is declared, therefore all launchers supposedly enforce its authority.
- A budget is recorded, therefore spending is supposedly bounded while work happens.
- An agent has a default model, therefore its descendants supposedly used that model.
- A review status is green, therefore independent examination supposedly occurred.
- A file or message exists, therefore the next responsible person supposedly received and accepted it.
- A component or durable store exists, therefore the operative caller supposedly uses it.

This produces both overconfidence and unnecessary reinvention. When the real caller is missing, another spec or orchestrator is created instead of repairing the transition. When a working path is overlooked, its capability is rediscovered and rebuilt. The failure mode is amplified by large inherited contexts: historical prescriptions stay salient, while narrow current qualifications and recent corrections are lost among them.

The corrective method is modest: for each consequential transition, identify **who requests it, which predicate permits it, which implementation changes state, what the next consumer observes, and what remains unknown after interruption**. Reuse native identifiers and existing artifacts rather than creating a duplicate ontology for ordinary progress. Add a record only where crossing a role/runtime/effect boundary loses necessary evidence.

**Late remote evidence, explicitly self-reported:** while this report was being completed, R2 appended a healer incident stating that it terminated a registered peer session after inspecting process/worktree/merged-PR state, and only afterward read the immediately preceding ledger row identifying that session as operator-owned and not idle. The same addition records a notification and a new instruction to check peer registration before termination. This audit verified the committed statement and its chronology, **not the underlying process termination or notification independently**. It is a particularly direct counterexample: fresh technical observations and merged code did not establish authority to close the session. Another prose instruction is not proof that the next destructive caller will enforce ownership. No process-control or recovery action was taken in this analysis. [R2: `.claude/skills/modus/PENDING-ARMS.md:1895–1896`; [pinned remote ledger](https://github.com/Bali-Zero/Teman2/blob/ddc83abd5c58fb14bc098210a7f10e7e38be9fb7/.claude/skills/modus/PENDING-ARMS.md#L1895).]

A second pattern appears in the 113-agent script: **verification can reproduce the problem's size twice instead of selecting the risks that warrant independent attention**. Two refuters per finding create 106 contexts before one synthesis. This may be justified for some findings, but the multiplicative cost is not justified merely by the label “deep audit.” Independent review should preserve a fixed coverage denominator while using task-selected depth, sampling only when explicitly authorized and reported. “One agent is always cheaper” is also not an evidence-based universal rule.

There are genuine strengths worth retaining: immutable-base risk classification, head-bound status reads, isolated worktrees, the distinction between code and live consumer, native replay, and the explicit refusal of unqualified effectful adapters. They already embody the state-transition discipline. The minimum migration should extend their coverage rather than replace their underlying method.

### One operational base per mission

Use one qualified operational runtime to own the mission's working context, progress and ordinary continuation. Choose it for the actual work and available capacity. Opus/Claude-native and Sol/Codex-native are peer alternatives; neither is a permanent subordinate or final reviewer. The imperators establish strategic constraints and appoint a temporary Dux, then intervene at material decisions or exceptions. A small mission may use only a Dux plus one independent reviewer. Specialist and support ranks are optional responsibilities, not seats that must be occupied.

Call another family when it supplies a specific advantage: independent verification, a qualified specialist, long-context ingestion, a local-private capability, or available eligible capacity. Native-first must not become native-only dogma. Conversely, subscription ownership is not a reason to distribute work across every vendor.

The existing Gear-2+ rule for two-or-more builder lanes requires non-Anthropic build participation. Zero must decide whether to retain that requirement or replace it with responsibility-based independence under the current hierarchy. Until changed, a native Claude-only multi-builder proposal conflicts with that predicate. One builder with independent review is already a simpler permissible shape. An external opinion must not be relabeled a build solely to satisfy the checker.

1. **Freeze the authoritative delta and its consumers.** Review C1's partial doctrine/reviewer work and the existing packet-builder PR. 2. **Repair the existing launch paths before inventing another.** Model-pin the consumed templates; validate intended and effective models/effort; preserve incomplete reviewer denominators. 3. **Complete one review/accounting consumer.** Independently review C1/C2 against frozen artifacts, resolve their effective enforcement dates, and demonstrate the exact CI/collector caller on a harmless fixture. Reuse the native usage ledger. Keep provisional, missing and external usage explicit.
4. **Use native continuation inside the base runtime.** At cross-runtime boundaries only, retain a compact mission/task identity, parent, artifact hash, expected result, expiry and accepted/completed state. Reuse the existing appointment/admission store if it fits. Do not wrap every native progress update in a second database event.
5. **Add reservation only where capacity can actually race.** If a mission permits overlapping external descendants, qualify atomic reserve/release/expiry against the existing store. A single sequential external task may not need a fleet allocator. Unknown-running work continues to consume the reservation until reconciliation; expiry alone must not authorize duplicate effects.
6. **Run the bounded pilot below after separate authorization.** Promote only those candidate consumers that pass. Roll back or suspend the specific failed route. No mass migration, always-on scheduler or automatic software upgrade is justified by this analysis.

### Framework decision

LangGraph is already a backend capability, including a conditional RAG orchestrator path. That is not proof it is the development-mission coordinator. A graph with a persistent checkpointer can provide restartable state; the framework need not be a daemon. It also does not automatically establish authorized identity, review independence, transactional account reservation or idempotent external effects. [R: `apps/backend-rag/backend/services/rag/agentic/orchestrator.py:206–232`; [official LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence).]

**No demonstrated gap currently requires a new LangGraph mission system.** Reconsider only if a bounded pilot shows a necessary mission cannot recover or coordinate across the qualified runtimes using native replay plus existing state/adapters, and a minimal graph demonstrably replaces missing behavior rather than duplicating an existing owner. A framework earns its place by reducing unresolved transitions and operational burden in that test. It does not earn it by being durable in a comparison table.

The strongest counterexample to this recommendation would be a mission with essential long-lived, cross-host, effectful branches whose recovery cannot be safely delegated to any one native base. Such a case may need a durable coordinator. The present dossier demonstrates narrower prototype/qualification gaps, not that counterexample in production.

## 8. A falsifiable pilot, preregistered before execution

**Not run and not authorized by this report.** Proposed protocol `P1` tests the smallest qualifying implementation. It is not permission to launch a workflow, stop a live process or activate a broker. Thresholds below are proposed experimental limits, not measurements or existing policy.

**Hypothesis:** existing native execution plus corrected present consumers can deliver a frozen, independently verified task with differentiated contexts and honest recovery; a new general coordinator is unnecessary for that mission class.

**Fixture:** two isolated copies of the same small, non-client repository task with a locked specification, bounded file set and a hidden acceptance suite frozen by an eligible non-contributor. Include one known correctness defect, one stale-artifact trap, one omitted-model launch request and one deliberately unavailable review response. Effects are restricted to disposable files; no network writes, production access, secrets, customer data or paid-key calls. Existing implementation is selected and reviewed before the clock starts.

**Comparison:** A uses the smallest existing qualified route; B uses that route with the proposed policy/consumer alignment. Each case is run once. Freeze the base runtime/model/effort, task and acceptance suite for comparability; if capacity forces a substitution, label the comparison non-equivalent and do not claim an efficiency win. Testing a second native family is a subsequent portability test, not an extra parallel team in P1.
