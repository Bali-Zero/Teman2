# GAP — frontend serves clients/team but has NO agent that could help

These feed "game-changer" proposals. Ordered by client-impact.

### GAP-1 (CRITICAL, public-facing) — Public site advertises a 24/7 AI but the button is dead
`ZantaraFAB` ("Ask Zantara · AI · Online 24/7") is mounted on the public blog + marketing site (`(blog)/layout.tsx`, `(marketing)/page.tsx`) but is a **pure presentational `<button>` with no onClick / no chat**. The fully-built public widget (`ZantaraWidget`, with anonymous SSE chat + auto CRM-lead capture via `POST /api/crm/clients`) exists but is mounted ONLY in `.backup` files. Net effect: every public visitor sees a "live" AI pill that does nothing, and the lead-capture funnel is dark. **Game-changer: wire ZantaraFAB → ZantaraWidget (the backend `/api/agentic-rag/stream` is already live).** Lowest-effort, highest-revenue gap in the whole zone.

### GAP-2 (HIGH, client portal) — Client portal has NO AI assistant, only human messaging
`apps/mouth/src/app/portal/(authenticated)/chat/page.tsx` is human↔team messaging (30s polling, `api.portal.getMessages`, `send_portal_message`) — NOT AI. The authenticated CLIENT portal (`portal/(authenticated)/{messages,taxes,documents,timeline,visa-status}`) has zero agentic surface, even though backend MCP exposes `get_portal_dashboard`, `get_portal_visa_status`, `get_portal_timeline`, `list_portal_documents`. **Game-changer: a client-facing copilot inside the portal** that answers "where is my visa / what's my next deadline / what does this document mean" — the agentic-rag + portal data already exist server-side; only the client never gets an AI, while the team does (WorkspaceAssistant on every workspace page).

### GAP-3 (HIGH, OSINT) — Intelligence KG dashboard with no natural-language interrogation
`osint-nexus-ui` is a rich Neo4j graph of officials/orgs/relationships but is **click-only Cypher viz** — no search box, no NL query, no agent. Backend already has `kg_intel_search` / `kg_intel_entity` / `naga_research` MCP tools. **Game-changer: an "ask the graph" agent** ("who connects official X to org Y", "show recent asset deltas for province Z") layered over the existing Cypher API. (Respect Symbiosis Law 2 — OSINT stays on-Pro; this UI is already local/sovereign.)

### GAP-4 (HIGH, WA operations) — WhatsApp dashboard shows AI drafts but has no generative copilot
`wa-dashboard` displays a backend-precomputed `suggested_message_draft` per action but provides no in-UI generation, no "draft a reply to this thread", no AI triage/prioritization beyond the static queue, and no one-click "send suggested draft". Operators handle WA actions manually. **Game-changer: an interactive reply-drafting + thread-summary agent** in the action row (the wa-mirror context + agentic-rag are both live). Note: send-side automation must respect the "never auto-publish" guardrails.

### GAP-5 (MEDIUM, admin/legal) — Legal corpus browser has search but no Q&A agent
admin-dashboard `/legal` lets you filter/search chunks; admin `/rag` lets you debug retrieval. Neither lets an admin **ask a legal question in natural language** and get a cited answer — despite `ask_legal` existing as an MCP tool and the full agentic-rag stack being live. **Game-changer: drop the existing chat surface (or an `ask_legal` panel) into the admin legal view** so internal legal research isn't "grep the chunks."

### GAP-6 (MEDIUM, fragmentation) — Three+ separate "Zantara chat" frontends on two backends
Genuine agentic chat is split across: mouth `/chat` + Terminal + WorkspaceAssistant + ZantaraWidget (→ `agentic-rag`), the standalone `web`/zantara.balizero.com `/chat` (→ V6 **graph-engine** `/api/query`), and kbli-navigator's ZantaraChat (→ `kbli-notebook/chat`). Different backends, duplicated streaming/SSE parsers, divergent UX (ConfidenceIndicator only in `web`; ToolUse/Thinking/NLM-citations only in `mouth`). **Game-changer (consolidation): one shared chat-agent surface + one streaming contract**, so confidence scoring, tool-step display, and citations are uniform — and so the public, portal, and KBLI entry points all reuse the richest UI instead of three thinner ones.

### GAP-7 (LOW, content) — `/dream` AI content tool partially mocked
`dream/page.tsx:1471` comment + `useState<any>` mock state indicate the "generate ALL formats" path is still partly mock rather than real `dreamApi.generate` calls. Not client-facing, but the AGENTIC content surface is incomplete vs its UI promise.
