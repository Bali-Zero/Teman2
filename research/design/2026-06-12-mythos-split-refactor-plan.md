# MYTHOS — "split" refactor plan (Visa + KBLI → real React code)

Antonello approved the **split** direction (two-column: wizard + live case-file for Visa;
register + permanent Zantara column for KBLI) over the v3 (one-column, too empty). This plan
turns that mockup into the real `apps/mouth` code, **in small verifiable phases** so the live
site is never broken mid-flight.

> **Reality check from the Explore map (why this is a refactor, not an edit):** the real KBLI
> ships its OWN dark anthracite theme (`styles/kbli-theme.css`, ~30 props, `#1d273b`), not Rumah
> Putih. The real Visa is a 4-step wizard (`AppWizard` from `@balizero/core`) with a separate
> result page (`AppStampReveal`/checklist/alternatives/ChatAccordion). ~20 files, 2 themes, real
> wizard flows. So: phased, one page at a time, render-checked each phase.

## 1. Hard constraints (carry through every phase)

- **Theme fixed**: paper #f6f4ef/#f7f6f2, navy #1e3863, ONE red #FF2D4C per viewport, Cormorant + Inter, no photos. Reuse RUMAH_VARS where it fits; extend with the split tokens.
- **Prices NEVER hardcoded** (Golden Rule #11): the 20M/5M strings in KBLIConsultationCTA must come from the synced source-of-truth module (`apps/mouth/data/bali-zero-prices.json` generated by `scripts/sync_frontend_prices.py`, CI-checked) — values are REAL (PT PMA 20M, Virtual Office 5M, verified `search_service_pricing`), only the SOURCE changes.
- **NavShell + Footer stay dark** — apply theme on `<main>` per-page (the leak trap: never on shared layout).
- **One red per viewport** — wordmark/nav/rule navy; red only on the single primary action (Visa handoff / KBLI "Talk to a human").
- **Funnel-event parity** — any new analytics event must be added to BOTH FUNNEL_EVENTS and backend ALLOWED_EVENTS or the parity test fails.
- **No auto-merge** — every phase = its own branch + PR, gated, render-verified, Antonello approves before merge. No `--no-verify`/`--amend`/force-push.

## 3. Risks & how each is handled

| Risk | Handling |
|---|---|
| KBLI dark theme rewrite breaks badges/licensing | Phase 1 only touches `[code]` `<main>`; badges re-styled in isolation; LicensingSection kept, re-themed via scoped `.rumah-putih` overrides, not deleted |
| Theme leak to NavShell/Footer (the known trap) | Theme applied on `<main>` per-page, NEVER on shared layout. Phase 0 AC greps for shared-layout mutation = 0 |
| Funnel-event parity test fails on new event | Any new event added to BOTH FUNNEL_EVENTS + backend ALLOWED_EVENTS in the same PR; run parity test as AC |
| Hardcoded-price regression | Phase 1 AC: `grep 20.000.000 / 5.000.000` in components = 0; values come from synced module; sync script CI-checked |
| Wizard flow break (AppWizard from core) | Phases 3/4 keep the core wizard logic; only the presentation layer changes; e2e visa-funnel-fusion as gate |
| Big-bang breakage | One page per phase, own branch+PR, render-verified, Antonello approves before merge. Live site only changes one page at a time |
| SSR crash masked by hydrated screenshot (past scar) | Verify each phase via `next build` + curl SSR HTML, NOT only browser screenshot |

## 4. Sequencing rationale
KBLI detail first (Phase 1) because: (a) it carries the hardcoded-price Golden-Rule violation — fix it in the same pass; (b) it's the most self-contained page; (c) it's the clearest expression of the panel's KBLI direction (register + Zantara column). Visa result (Phase 3) before wizard (Phase 4) because the case-file is the payoff the wizard feeds — get the destination right first.
